# Ludex

Launcher hub pour Windows : détecte les jeux installés de tous les launchers (Steam, Epic, Riot pour l'instant) et les lance depuis une seule interface. Objectif : plus moderne et plus beau que Playnite ou GOG Galaxy.

## Stack

- Tauri 2 (Rust, edition 2024) dans `src-tauri/`
- React 19 + TypeScript + Vite dans `src/`
- Polices embarquées via @fontsource-variable : Geist (interface), Geist Mono (chiffres, méta, touches)

## Commandes

- `npm run tauri dev` : lance l'app
- `npx tsc --noEmit` puis `npm run build` : vérif front
- `cd src-tauri && cargo test` : tests Rust
- `cd src-tauri && cargo test scan_this_pc -- --ignored --nocapture` : scan réel du PC (avec temps de jeu, les 5 jeux les plus joués et les succès Steam)
- `cd src-tauri && cargo test achievements_this_pc -- --ignored --nocapture` : coût des succès dans le scan Steam
- `cd src-tauri && cargo test processes_this_pc -- --ignored --nocapture` : relevé réel des processus, jeux de la bibliothèque déjà ouverts
- `cd src-tauri && cargo test images_this_pc -- --ignored --nocapture` : scan réel puis téléchargement des images manquantes dans `%TEMP%\ludex-images-this-pc` (jamais le dossier de l'app)
- `cd src-tauri && cargo test details_this_pc -- --ignored --nocapture` : fiches réelles (genres, studio, année) de la bibliothèque, sans toucher aux caches de l'app
- `cd src-tauri && cargo clippy --all-targets` : doit rester sans avertissement

## Architecture

- `src-tauri/src/library/` : une source par launcher (`steam.rs`, `epic.rs`, `gog.rs`, `ubisoft.rs`, `ea.rs`, `battlenet.rs`, `rockstar.rs`, `xbox.rs`, `riot.rs`, puis `local.rs` pour « Autres »), lecture de fichiers locaux et du registre uniquement, aucune connexion à un compte. `vdf.rs` parse le format texte de Valve, `kvbin.rs` le KeyValues binaire (chaînes empruntées au fichier, `None` si tronqué ou type inconnu). `mod.rs` définit `Game`, `Launch`, `ScanResult`, les utilitaires `reg` (registre en lecture) et `xml_attr`, et agrège les sources dans l'ordre de priorité : `Ok(None)` = launcher absent, `Ok(Some(vec![]))` = installé sans jeu ; un jeu dont le dossier est déjà vu par une source précédente (même dossier, parent ou sous-dossier) est écarté.
- Sources : GOG (registre `GOG.com\Games`, lancement par Galaxy ou l'exe), Ubisoft (registre `Ubisoft\Launcher\Installs`, `uplay://launch/<id>/0`), Rockstar (registre `Rockstar Games`, exe `Play*.exe`, images Steam via une table titre → appid), Xbox (registre des paquets MSIX, jeu = `MicrosoftGame.config` à la racine, `explorer.exe shell:AppsFolder\<famille>!<app>`, visuel = écran de démarrage local). `Launch::Exec` part du dossier de l'exécutable.
- Dossiers de jeux (`local.rs`) : sous-dossiers des dossiers « Jeux » / « Games » à la racine des lecteurs (un « Jeux Epic » dedans est lu aussi, `XboxGames` exclu) et emplacements de la désinstallation Windows qui contiennent un moteur (Unity, Unreal, Steamworks), liste gardée 10 s pour un même scan. Chaque dossier est rangé : `.product.db` + `.build.info` = Battle.net (code produit → `battlenet://<code>` si le client est là, sinon l'exe), `__Installer\installerdata.xml` = EA (contentID, titre, exe non « trial » lancé directement), sinon « Autres » : exe choisi par score (nom proche du dossier, profondeur ≤ 3, taille, listes d'exclusion installeurs/utilitaires/anti-triche), titre = ProductName de l'exe (crate `pelite`) sinon dossier ou nom de l'exe ; launchers installés écartés, doublons de titre écartés. Plus des emplacements fixes : FiveM, RedM, RAGE MP, Roblox, jeux Ankama (lancés par l'Ankama Launcher), Pokeisland.
- `src-tauri/src/lib.rs` : commandes Tauri `scan_library`, `launch_game` (renvoie l'heure du lancement et démarre le suivi de session), `open_install_dir`, `set_favorite`, `set_hidden`, `game_sessions` (sessions en cours), `game_history` (sessions terminées d'un jeu, la plus récente d'abord). Jeux scannés, préférences et `Tracker` gardés dans `AppState`. Événement `game-session` : `{ id, phase: detecting|running|ended, playtimeMinutes, playtimeSource }`, le temps n'étant rempli que quand Ludex vient d'ajouter du temps. Protocole `ludex` (`http://ludex.localhost/<plateforme>/<id>/<cover|hero|logo|icon>` sous Windows) : sert les images locales d'un jeu de l'état (`Game.local_art`, jamais sérialisé ; `icon` = icône extraite de l'exe par `local::exe_icon`, PNG ou .ico), type lu dans la signature, `Cache-Control: no-cache` + `ETag` (taille, date) avec réponse 304. Événement `game-art` : `{ id, coverUrl, heroUrl, logoUrl }`, envoyé quand une jaquette vient d'être trouvée en ligne ou qu'une image vient d'entrer dans le cache disque.
- **Cache disque des images** (`src-tauri/src/images.rs`) : jaquette, image de fond et logo distants (CDN Steam) gardés dans `<données>/images/<plateforme>/<id nettoyé>/<cover|hero|logo>.<jpg|png|webp>`, index `images/index.json` (URL d'origine de chaque fichier, 404 notées, dernière présence de chaque jeu). Au scan, `ImageCache::apply` en dernier : une image distante déjà en cache (même URL d'origine) passe sur `local_art` + URL `ludex` ; les images locales du launcher restent prioritaires et ne sont jamais copiées. Fil `resolve_images` après chaque scan et après `resolve_art` (`images_busy`) : 4 téléchargements à la fois, jaquettes d'abord, arrêt après 3 erreurs réseau de suite, puis `game-art` par image. Règles : téléchargement seulement depuis les URL de l'état, hôtes en liste blanche stricte (`cdn.cloudflare.steamstatic.com`, `shared.akamai.steamstatic.com`, sans requête ni `..`), redirections jamais suivies, 8 Mo au plus, JPEG/PNG/WebP vérifiés par signature, écriture tmp + renommage, id nettoyé (`clean_id` : ASCII minuscule, empreinte FNV si modifié, noms réservés Windows évités). 404 (ou 403, 410, redirection, image invalide) notée et redemandée après 7 jours. Purge : dossier d'un jeu absent de la bibliothèque depuis 60 jours supprimé, pas de plafond global (la taille suit la bibliothèque). Les origines CDN restent dans `img-src` pour le premier affichage. Événement `game-details` : `{ id, details }`, envoyé quand une fiche arrive ou change.
- **Jaquettes hors Steam** (`src-tauri/src/art.rs`) : pour chaque jeu sans jaquette (hors Steam), titre cherché dans la recherche publique de la boutique Steam (`storesearch`, aucun compte, crate `ureq`), correspondance stricte (`same_game` : égalité, nom Steam qui finit par le titre, faute de frappe sans changer les nombres), table `DELISTED` pour les jeux retirés de la vente (FC, FIFA, Football Manager…). Chemins exacts des images lus dans `IStoreBrowseService/GetItems` (jeux récents : chemins hachés sur `shared.akamai.steamstatic.com`), sinon adresse classique du CDN. Cache `art-cache.json` (dossier de données) : trouvé = gardé, introuvable = recherché après 30 jours, `MATCHING_VERSION` à augmenter pour tout relancer. Recherche dans un fil après chaque scan, 350 ms entre deux titres. Sans jaquette : l'icône de l'exe sur la jaquette générée (`iconUrl`). L'appid retenu est gardé dans `Game.steam_appid`.
- **Fiches** (`src-tauri/src/metadata.rs`, `Game.details` : genres, développeurs, éditeurs, `releaseDate` en secondes Unix, description courte) pour tout jeu avec `Game.steam_appid` (Steam, table Rockstar, jeux retrouvés par `art.rs`, jamais sérialisé). API publique `IStoreBrowseService/GetItems` (`include_basic_info`, `include_release`, `include_tag_count` 20, `language` french), 40 appids par requête, 1 s entre deux lots. Genres = étiquettes de genre de `GENRES` (Action, Aventure, Stratégie, RPG…, sans Free-to-play, Accès anticipé ni Indépendant) par votes décroissants, trois au plus ; date = sortie d'origine sinon sortie Steam. Cache `metadata-cache.json` : appid redemandé après 30 jours, une fiche connue n'est jamais effacée par une réponse vide, `CACHE_VERSION` pour tout relancer. Fil après chaque scan et après la recherche des jaquettes (nouveaux appids), `meta_busy` contre les doublons ; une erreur réseau arrête la lecture.
- `src-tauri/src/store.rs` : préférences (favoris, masqués, outils ré-affichés, dernier lancement Ludex, temps mesuré par Ludex en secondes dans `playtime`) dans `user-data.json` du dossier de données de l'app (`%APPDATA%/com.ludex.app`).
- **Temps de jeu** (`Game.playtime_minutes` + `playtime_source` : `launcher` ou `ludex`, jamais additionnés ; `None` = inconnu) :
  - Steam : `userdata/<steamid3>/config/localconfig.vdf`, `UserLocalConfigStore > Software > Valve > Steam > apps > <appid>` (`Playtime` en minutes, `LastPlayed`). Compte : `config/loginusers.vdf`, `MostRecent` = 1 sinon `timestamp` le plus récent (le Steam actuel n'écrit plus `MostRecent`), steamid3 = SteamID64 − 76561197960265728 ; repli sur le `localconfig.vdf` le plus récent de `userdata`. Appli absente du fichier = 0 min.
  - GOG : base de Galaxy `ProgramData\GOG.com\Galaxy\storage\galaxy-2.0.db` (SQLite via `rusqlite` `bundled`, lecture seule), tables `GameTimes` (`releaseKey` = `gog_<id>`, `minutesInGame`) et `LastPlayedDates`. Seulement si le jeu est lancé par Galaxy.
  - Epic, Ubisoft, Rockstar, Xbox, Riot : aucune donnée locale fiable (fichiers chiffrés ou temps côté serveur), donc mesure par Ludex.
  - `src-tauri/src/session.rs` : mesure par Ludex. `Tracker` = un fil qui dort sans session ; après `launch_game`, relevé toutes les 5 s (crate `sysinfo`, chemins d'exécutables mis en cache) des processus situés sous le dossier du jeu (plus `%LOCALAPPDATA%\Packages\<famille>` pour Xbox ; racines trop larges refusées). Détection jusqu'à 10 min après le lancement, absence tolérée 5 min tant que la session fait moins d'une minute (lanceur intermédiaire type `PlayGTAV.exe`), 30 s ensuite. Écart de plus de 20 s entre deux relevés (veille) non compté, sessions de moins d'une minute ignorées, plafond 24 h. Cumul enregistré chaque minute. Steam et GOG Galaxy (`launcher_tracks_playtime`) sont suivis pour « En jeu » mais jamais cumulés.
  - `src-tauri/src/history.rs` : historique dans `sessions.json` (dossier de données de l'app, une session par ligne : `{ gameId, start, secs, launcher }`, secondes Unix et secondes de jeu, `launcher` = Steam ou Galaxy, temps de référence du launcher, jamais additionné). Toute session d'une minute au moins y va, réécrit en entier (tmp + rename) à sa fin ; au-delà de 5 000 sessions, la moitié ancienne est fusionnée par jeu et par jour UTC, puis les plus anciennes retirées. Sessions en cours dans `session-en-cours.json` (dossiers surveillés, début, dernier relevé, secondes mesurées et déjà cumulées), réécrit à chaque relevé qui change, supprimé quand rien ne tourne. Reprise : au démarrage, `Tracker::resume` (après la mise en place de l'état) relit ce fichier ; si un processus du jeu démarré avant le dernier relevé tourne encore, la session reprend (« En jeu », cumul qui continue) ; sinon elle est close au dernier relevé (historique + reste du cumul). PC redémarré depuis = close directement. Ordre d'écriture : historique, sessions en cours, puis cumul : un arrêt entre deux écritures perd au plus un relevé, jamais de double compte.
- **Succès Steam** (`achievements.rs`, `Game.achievements` = `{ unlocked, total, lastUnlocked }`, `None` = pas de succès ou pas de fichier) : `appcache/stats/`, compte = dossier `userdata` du `localconfig.vdf` retenu. `UserGameStatsSchema_<appid>.bin` : `<appid> > stats > <id> > bits > <n° de bit 0-31>` (type `ACHIEVEMENTS`), total = nombre d'entrées de `bits` (numéros parfois troués). `UserGameStats_<compte>_<appid>.bin` : `cache > <id> > data` (int32, masque des débloqués) et `AchievementTimes > <n° de bit>` (secondes Unix). Schéma sans fichier de progression = `None`, pas « 0 ». Lu pendant le scan Steam.
- Steam fournit `LastPlayed` et `SizeOnDisk`, Epic `InstallSize`. Images Steam : d'abord `appcache/librarycache/<appid>/` (à plat ou dans des sous-dossiers hachés, jaquette `library_600x900` ou `library_capsule`), sinon le CDN. Les outils (Wallpaper Engine, `* Editor`, `* Dedicated Server`…) sont `is_tool` : masqués par défaut, jamais exclus.
- **Sécurité** : le front n'envoie qu'un id de jeu. La commande de lancement et le dossier sont reconstruits côté Rust depuis l'état. Ne jamais exposer de commande qui prend un chemin ou une URI arbitraire venant du front. CSP stricte dans `tauri.conf.json` (`csp` et `devCsp`, appliquée seulement en build : `npx tauri build --no-bundle` pour la tester) ; toute nouvelle origine d'image va dans `img-src`. Le front n'a que `core:default` comme permission.
- `src/lib/api.ts` : types et appels `invoke`. `src/lib/color.ts` : couleur d'ambiance extraite de la jaquette (fallback : hash du titre).
- `src/lib/library.ts` : filtres, tri (Récents, Plus joués, A → Z, Taille), récents, préférences d'affichage (localStorage). `src/lib/format.ts` : dates relatives, tailles, temps de jeu (`formatPlaytime` : « 45 min », « 2,5 h », « 1 240 h », « Jamais joué », « Non mesuré »), recherche.
- `src/components/` : GameCard, LibraryGrid (colonnes mesurées, insère la fiche sous la rangée), GameStrip (fiche dépliable, ligne « genres · studio · année » avec développeurs, éditeurs et date au survol, description sur deux lignes, stat « Temps de jeu » avec sa provenance au survol, stat « Succès » si connue avec le dernier déblocage au survol, « Dernière session » avec la durée tirée de `game_history`), ResumeRow, Art et Logo, Cover, States, Icons. Mention `.live` « En jeu » sur la carte, la tuile et la fiche.
- `src/App.tsx` : écran unique « Focus » : grand champ de recherche, Reprendre, filtres et tri, grille, barre de raccourcis (taper n'importe où, flèches, Entrée, Espace, Échap, Ctrl+D, Ctrl+K, F5). Manette (`src/lib/gamepad.ts`, Gamepad API, ignorée quand Ludex n'a pas le focus) : croix ou stick naviguer, A jouer, X fiche, Y favori, B fermer, LB/RB filtre, LT/RT tri ; la barre du bas montre ces boutons après une action à la manette. Écoute `game-session` (ensemble `playing`, temps mis à jour en direct) et rescanne en silence 10 s après la fin d'une partie.

## Design system

- Tokens dans `src/styles/tokens.css` (préfixe `--lx-*`), styles dans `src/styles/app.css`.
- Logo : une touche de clavier turquoise avec le triangle « Jouer » (`assets/logo/ludex-mark.svg`, version avec le nom `ludex-lockup.svg`, composant `LudexMark`). Icônes de l'app régénérées par `npx tauri icon assets/logo/ludex-mark.svg` (supprimer ensuite `icons/android` et `icons/ios`).
- Palette validée : base monochrome (#0B0B0B, #1A1A1A, #242424, #333333, blanc) + accent turquoise #14B8A6. Thème clair via `[data-theme="light"]`. D'autres thèmes viendront plus tard : toujours passer par les tokens, jamais de couleur en dur.
- `--lx-ambient` : couleur dérivée du jeu sélectionné, réservée au contour de sélection. Bouton Jouer en blanc cassé (`--lx-text` sur `--lx-bg`).
- Passe unslop appliquée : grille de 4px, icônes 18px trait 1.5, graisses 400 à 600, pas de majuscules espacées, chiffres tabulaires, rayons s/m/l = 8/10/12, une seule courbe `--lx-ease`, survol sans déplacement (contour ou voile qui s'éclaircit), léger `scale` au clic.

## État actuel

- Testé sur le PC de l'utilisateur : Steam 69 jeux, Riot 2, Rockstar 1 (GTA V), Xbox 1 (Minecraft Launcher), Epic et Ubisoft installés sans jeu, GOG absent, EA 3 (FC 24, FIFA 21, NFS Rivals), Battle.net 1 (StarCraft II, client absent : lancé par l'exe), Autres 24 (Cyberpunk, Tarkov, Genshin, FiveM, Dofus, Roblox, Sims 4…). Epic, GOG et Ubisoft avec jeux testés seulement en unitaire. Jaquettes trouvées sur Steam pour 15 jeux « Autres » et EA (Cyberpunk, Tarkov, Sims 4, FC 24, Football Manager…) ; icône de l'exe pour les autres (Dofus, Genshin, FiveM, Roblox, StarCraft II…). Aucun de ces jeux n'a été lancé. Scan complet ~2,5 s en debug, dont 1,6 s pour « Autres ».
- Temps de jeu (branche `temps-de-jeu`) : Steam lu sur ce PC pour les 69 jeux ; GOG testé seulement en unitaire ; mesure par Ludex testée en unitaire et par un relevé réel des processus, pas encore sur une vraie partie. Historique et reprise (branche `historique-sessions`) testés en unitaire et par un relevé réel des processus, pas sur une vraie partie ; la fiche affiche « Dernière session : il y a 2 jours, 1 h 20 ». Limites : jeu lancé hors de Ludex non mesuré ; temps passé pendant que Ludex était fermé non compté (écart > 20 s), le suivi reprend au redémarrage ; client Riot (`LeagueClient.exe`) compté comme du jeu ; processus protégés dont le chemin est illisible (certains anti-triche) non vus ; `PlaytimeDisconnected` de Steam ignoré.
- Fiches (branche `metadonnees`) : 85 jeux sur 100 en ont une sur ce PC (83 appids, 3 requêtes) ; affichage minimal dans la fiche, vérifié seulement par `tsc` et le build, pas à l'écran. Pas de filtre par genre. Genres tirés des étiquettes votées : parfois discutables (Wallpaper Engine « Action »).
- Refonte UI « Focus » faite (branche `refonte-ui-focus`). Audit et maquettes : `maquettes/refonte-ui.html` (non versionné).
- Succès (branche `succes-steam`) : 63 jeux Steam sur 69 ont des succès sur ce PC (les 6 autres n'ont aucun fichier dans `appcache/stats`), dates de déblocage présentes pour chaque succès débloqué. Coût : ~100 ms en debug sur un scan Steam de ~220 ms, ~50 ms en release sur ~160 ms (schéma PAYDAY 2 de 3,4 Mo). Limites : cache tenu par le client Steam, moment de sa mise à jour non vérifié (un succès tout récent peut manquer) ; jeux non installés ignorés ; seulement Steam ; pas encore vu dans l'interface.
- Cache des images (branche `cache-images`) : relevé réel (`cargo test images_this_pc -- --ignored --nocapture`, dossier temporaire) : 100 jeux, 55 images distantes à télécharger (les jeux Steam ont surtout leur `librarycache`), 51 téléchargées, 4 absentes (404 : logo de Tarkov, images de l'appid 1624110), 9,5 Mo, 18 jeux servis par le cache, 3,6 s scan compris ; second passage : rien à télécharger, 2,3 s. Pas encore vu dans l'interface (passage de l'URL CDN à l'URL `ludex`, revalidation 304 par la WebView non vérifiée).
- Problèmes connus : jeux Riot sans images (jaquette générée avec icône). Titre tiré d'un dossier mal nommé (« Crusader King ») non reconnu sur Steam. Amis pas commencés ; succès hors Steam pas commencés.
- Dépendances Rust ajoutées : `sysinfo` (sans fonctions par défaut, `system`) `rusqlite` (`bundled`, compile SQLite : premier build plus long), `pelite` (Windows : ProductName et icônes des exe), `ureq` 2 (recherche des jaquettes et des fiches, cache des images).
- Idées et tâches : projet Ludex du tableau « Tâches NRW » (https://claude.ai/artifact/LLukjvgWpKWsVhMMez4a8t).
