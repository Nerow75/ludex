# Ludex

Launcher hub pour Windows : détecte les jeux installés de tous les launchers (Steam, Epic, Riot pour l'instant) et les lance depuis une seule interface. Objectif : plus moderne et plus beau que Playnite ou GOG Galaxy.

## Stack

- Tauri 2 (Rust, edition 2024) dans `src-tauri/`
- React 19 + TypeScript + Vite dans `src/`
- Polices embarquées via @fontsource-variable : Geist (interface), Geist Mono (chiffres, méta, touches)

## Commandes

- `npm run tauri dev` : lance l'app
- `npx tsc --noEmit` puis `npm run build` : vérif front
- `cd src-tauri && cargo test` : tests Rust
- `cd src-tauri && cargo test scan_this_pc -- --ignored --nocapture` : scan réel du PC (avec temps de jeu, les 5 jeux les plus joués, les succès Steam et les jeux pas prêts : mise à jour, téléchargement)
- `cd src-tauri && cargo test achievements_this_pc -- --ignored --nocapture` : coût des succès dans le scan Steam
- `cd src-tauri && cargo test processes_this_pc -- --ignored --nocapture` : relevé réel des processus, jeux de la bibliothèque déjà ouverts
- `cd src-tauri && cargo test images_this_pc -- --ignored --nocapture` : scan réel puis téléchargement des images manquantes dans `%TEMP%\ludex-images-this-pc` (jamais le dossier de l'app)
- `cd src-tauri && cargo test details_this_pc -- --ignored --nocapture` : fiches réelles (genres, studio, année) de la bibliothèque, sans toucher aux caches de l'app
- `cd src-tauri && cargo test watched_this_pc -- --ignored --nocapture` : dossiers surveillés sur ce PC
- `cd src-tauri && cargo test watches_a_steam_library -- --ignored --nocapture` : surveillance réelle d'un faux `steamapps` (anti-rebond, ~13 s)
- `cd src-tauri && cargo test saves_this_pc -- --ignored --nocapture` : base des sauvegardes téléchargée dans `%TEMP%\ludex-saves-this-pc`, puis jeux de la bibliothèque dont des sauvegardes sont trouvées (emplacements, tailles), sans rien copier ni toucher aux dossiers de l'app
- `cd src-tauri && cargo clippy --all-targets` : doit rester sans avertissement
- Installeur local (PowerShell) : `$env:TAURI_SIGNING_PRIVATE_KEY = "$env:USERPROFILE\.tauri\ludex-updater.key"; $env:CI = "true"; npx tauri build` (`CI` = mot de passe vide, sans invite). Produit `src-tauri/target/release/bundle/nsis/Ludex_<version>_x64-setup.exe` et son `.sig`. Sans la clé, la build échoue (`createUpdaterArtifacts`) : `npx tauri build --no-bundle` pour tester la CSP seulement.
- Release : monter la version dans `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` et `package.json` (les trois identiques), committer, puis `git tag v<version>` et `git push origin v<version>` : le workflow `.github/workflows/release.yml` construit et publie.

## Architecture

- `src-tauri/src/library/` : une source par launcher (`steam.rs`, `epic.rs`, `gog.rs`, `ubisoft.rs`, `ea.rs`, `battlenet.rs`, `rockstar.rs`, `xbox.rs`, `riot.rs`, puis `local.rs` pour « Autres »), lecture de fichiers locaux et du registre uniquement, aucune connexion à un compte. `vdf.rs` parse le format texte de Valve, `kvbin.rs` le KeyValues binaire (chaînes empruntées au fichier, `None` si tronqué ou type inconnu). `mod.rs` définit `Game`, `Launch`, `ScanResult`, les utilitaires `reg` (registre en lecture) et `xml_attr`, et agrège les sources dans l'ordre de priorité : `Ok(None)` = launcher absent, `Ok(Some(vec![]))` = installé sans jeu ; un jeu dont le dossier est déjà vu par une source précédente (même dossier, parent ou sous-dossier) est écarté.
- Sources : GOG (registre `GOG.com\Games`, lancement par Galaxy ou l'exe), Ubisoft (registre `Ubisoft\Launcher\Installs`, `uplay://launch/<id>/0`), Rockstar (registre `Rockstar Games`, exe `Play*.exe`, images Steam via une table titre → appid), Xbox (registre des paquets MSIX, jeu = `MicrosoftGame.config` à la racine, `explorer.exe shell:AppsFolder\<famille>!<app>`, visuel = écran de démarrage local). `Launch::Exec` part du dossier de l'exécutable.
- Dossiers de jeux (`local.rs`) : sous-dossiers des dossiers « Jeux » / « Games » à la racine des lecteurs (un « Jeux Epic » dedans est lu aussi, `XboxGames` exclu) et emplacements de la désinstallation Windows qui contiennent un moteur (Unity, Unreal, Steamworks), liste gardée 10 s pour un même scan. Chaque dossier est rangé : `.product.db` + `.build.info` = Battle.net (code produit → `battlenet://<code>` si le client est là, sinon l'exe), `__Installer\installerdata.xml` = EA (contentID, titre, exe non « trial » lancé directement), sinon « Autres » : exe choisi par score (nom proche du dossier, profondeur ≤ 3, taille, listes d'exclusion installeurs/utilitaires/anti-triche), titre = ProductName de l'exe (crate `pelite`) sinon dossier ou nom de l'exe ; launchers installés écartés, doublons de titre écartés. Plus des emplacements fixes : FiveM, RedM, RAGE MP, Roblox, jeux Ankama (lancés par l'Ankama Launcher), Pokeisland.
- `src-tauri/src/lib.rs` : commandes Tauri `scan_library`, `launch_game` (renvoie l'heure du lancement et démarre le suivi de session), `open_install_dir`, `set_favorite`, `set_hidden`, `game_sessions` (sessions en cours), `game_history` (sessions terminées d'un jeu, la plus récente d'abord), `add_game`, `change_executable`, `rename_game`, `remove_game` (voir « Jeux ajoutés à la main »), `game_saves`, `backup_saves`, `restore_saves`, `choose_saves_dir`, `set_auto_saves`, `saves_overview` (voir « Sauvegardes »). Jeux scannés, préférences et `Tracker` gardés dans `AppState`. Événement `game-session` : `{ id, phase: detecting|running|ended, playtimeMinutes, playtimeSource }`, le temps n'étant rempli que quand Ludex vient d'ajouter du temps. Protocole `ludex` (`http://ludex.localhost/<plateforme>/<id>/<cover|hero|logo|icon>` sous Windows) : sert les images locales d'un jeu de l'état (`Game.local_art`, jamais sérialisé ; `icon` = icône extraite de l'exe par `local::exe_icon`, PNG ou .ico), type lu dans la signature, `Cache-Control: no-cache` + `ETag` (taille, date) avec réponse 304. Événement `game-art` : `{ id, coverUrl, heroUrl, logoUrl }`, envoyé quand une jaquette vient d'être trouvée en ligne ou qu'une image vient d'entrer dans le cache disque.
- **Cache disque des images** (`src-tauri/src/images.rs`) : jaquette, image de fond et logo distants (CDN Steam) gardés dans `<données>/images/<plateforme>/<id nettoyé>/<cover|hero|logo>.<jpg|png|webp>`, index `images/index.json` (URL d'origine de chaque fichier, 404 notées, dernière présence de chaque jeu). Au scan, `ImageCache::apply` en dernier : une image distante déjà en cache (même URL d'origine) passe sur `local_art` + URL `ludex` ; les images locales du launcher restent prioritaires et ne sont jamais copiées. Fil `resolve_images` après chaque scan et après `resolve_art` (`images_busy`) : 4 téléchargements à la fois, jaquettes d'abord, arrêt après 3 erreurs réseau de suite, puis `game-art` par image. Règles : téléchargement seulement depuis les URL de l'état, hôtes en liste blanche stricte (`cdn.cloudflare.steamstatic.com`, `shared.akamai.steamstatic.com`, sans requête ni `..`), redirections jamais suivies, 8 Mo au plus, JPEG/PNG/WebP vérifiés par signature, écriture tmp + renommage, id nettoyé (`clean_id` : ASCII minuscule, empreinte FNV si modifié, noms réservés Windows évités). 404 (ou 403, 410, redirection, image invalide) notée et redemandée après 7 jours. Purge : dossier d'un jeu absent de la bibliothèque depuis 60 jours supprimé, pas de plafond global (la taille suit la bibliothèque). Les origines CDN restent dans `img-src` pour le premier affichage. Événement `game-details` : `{ id, details }`, envoyé quand une fiche arrive ou change.
- **Jaquettes hors Steam** (`src-tauri/src/art.rs`) : pour chaque jeu sans jaquette (hors Steam), titre cherché dans la recherche publique de la boutique Steam (`storesearch`, aucun compte, crate `ureq`), correspondance stricte (`same_game` : égalité, nom Steam qui finit par le titre, faute de frappe sans changer les nombres), table `DELISTED` pour les jeux retirés de la vente (FC, FIFA, Football Manager…). Chemins exacts des images lus dans `IStoreBrowseService/GetItems` (jeux récents : chemins hachés sur `shared.akamai.steamstatic.com`), sinon adresse classique du CDN. Cache `art-cache.json` (dossier de données) : trouvé = gardé, introuvable = recherché après 30 jours, `MATCHING_VERSION` à augmenter pour tout relancer. Recherche dans un fil après chaque scan, 350 ms entre deux titres. Sans jaquette : l'icône de l'exe sur la jaquette générée (`iconUrl`). L'appid retenu est gardé dans `Game.steam_appid`.
- **Fiches** (`src-tauri/src/metadata.rs`, `Game.details` : genres, développeurs, éditeurs, `releaseDate` en secondes Unix, description courte) pour tout jeu avec `Game.steam_appid` (Steam, table Rockstar, jeux retrouvés par `art.rs`, jamais sérialisé). API publique `IStoreBrowseService/GetItems` (`include_basic_info`, `include_release`, `include_tag_count` 20, `language` french), 40 appids par requête, 1 s entre deux lots. Genres = étiquettes de genre de `GENRES` (Action, Aventure, Stratégie, RPG…, sans Free-to-play, Accès anticipé ni Indépendant) par votes décroissants, trois au plus ; date = sortie d'origine sinon sortie Steam. Cache `metadata-cache.json` : appid redemandé après 30 jours, une fiche connue n'est jamais effacée par une réponse vide, `CACHE_VERSION` pour tout relancer. Fil après chaque scan et après la recherche des jaquettes (nouveaux appids), `meta_busy` contre les doublons ; une erreur réseau arrête la lecture.
- **Sauvegardes** (`src-tauri/src/saves.rs`) : emplacements tirés du manifeste communautaire Ludusavi (`mtkennerly/ludusavi-manifest`, YAML d'environ 17 Mo). Revérifié au plus une fois par semaine (`If-None-Match` : un manifeste inchangé ne se retélécharge pas), lu entrée par entrée (`serde_yaml_ng`, visiteur) puis réduit à un index compact `saves/manifeste.json` du dossier de données (règles Windows seulement, jeux avec fichiers ou registre, alias ; ~6,5 Mo, `INDEX_VERSION`), le YAML n'est pas gardé ; hors ligne, l'index enregistré sert. En mémoire (`AppState.saves`, `saves::Known`), seulement les entrées des jeux de la bibliothèque : appid Steam (secondaires compris), id GOG, titre normalisé (alias compris), sinon nom du dossier d'installation ; fil `resolve_saves` après chaque scan (`saves_busy`). `Scope` : motifs développés (`<base>`, `<game>`, `<root>` = dossier de Steam, `<home>`, `<winAppData>`, `<winLocalAppData>`, `<winLocalAppDataLow>`, `<winDocuments>` = dossier connu, OneDrive compris, `<winPublic>`, `<winProgramData>`, `<winDir>`, `<osUserName>`, `<storeUserId>` = `*`, `<storeGameId>`), valeurs échappées pour `glob` (casse ignorée), règle d'une autre boutique écartée, réglage livré dans `<base>` (tag `config` seul) écarté, motif non absolu ou avec `..` refusé, chemin trouvé trop large refusé (lecteur, profil, AppData, Documents, dossier du jeu, `userdata` ou un de leurs parents), liens symboliques et jonctions jamais suivis, fichier déjà dans un dossier trouvé non repris. Registre ignoré (signalé `registry`). Copie : `<dossier>/<titre nettoyé>/<AAAA-MM-JJ_hh-mm-ss>[-n]/` en heure locale (crate `time`), `copie.json` (`{ gameId, title, created, reason: auto|manual|before_restore, size, files: [{ path, stored, size, modified }] }`) et fichiers sous `fichiers/<lecteur>/<chemin>`, écrite en `.tmp` puis renommée (restes `.tmp` effacés à la copie suivante), 1 Go ou 20 000 fichiers au plus, dossier des copies jamais copié dans lui-même. Copie identique à la précédente (chemins, tailles, dates) non refaite (`unchanged`). 10 copies par jeu (`rotate`, copies protégées jamais supprimées), copies d'un jeu gardées dans le même dossier même renommé, listées par `gameId` (`list_all` : un seul parcours). Copie automatique : `session::Update.finished` (session d'une minute au moins, close au relevé ou à la reprise) → fil `auto_backup` si `autoSaves` et jeu connu, événement `saves-backup` `{ id, title, copy, unchanged, error }` ; rien si aucune sauvegarde trouvée. Restauration (`restore_saves(id, backupId)`) : id de copie validé (`valid_copy_id`), refusée si le jeu tourne (`Tracker::active`, puis relevé ponctuel des processus `session::game_running`), tout vérifié avant d'écrire : chemin d'origine absolu sur un lecteur local, sans `..`, reconnu par une règle du manifeste de ce jeu (le chemin ou un parent), aucun lien symbolique ni jonction sur tout le chemin, fichier source ordinaire sous `fichiers/` ; puis copie de sécurité de l'état actuel (`before_restore`, sauf si rien à copier ou identique), écriture tmp + renommage, rotation qui protège la copie restaurée et la copie de sécurité. Les fichiers présents mais absents de la copie restent. Dossier par défaut `Documents\Ludex\Sauvegardes` (`default_dir`), changé par `choose_saves_dir` (sélecteur de dossier natif côté Rust, `check_dir` : absolu, dossier réel, écriture testée ; partage réseau accepté), le front ne reçoit que le texte. `saves_lock` : jamais deux copies ou restaurations à la fois.
- **Rescan automatique** (`src-tauri/src/watch.rs`, crate `notify`, lancé après le premier `scan_library`) : surveille sans récursion les `steamapps` de chaque bibliothèque Steam (`appmanifest_*.acf`), les manifestes Epic (`*.item`), `ProgramData\Riot Games` (`RiotClientInstalls.json`) et, avec récursion, son `Metadata` (`*.product_settings.yaml`), et les dossiers dont les sous-dossiers sont des jeux (`local::library_dirs` : « Jeux », « Games », « Jeux Epic » ; sous-dossier créé, supprimé ou renommé). Un manifeste touché est relu après 5 s de calme : rescan seulement si son état installé change (Steam `StateFlags` bit 4, Epic `bIsIncompleteInstall`), donc ni pendant un téléchargement ni pour une mise à jour. Anti-rebond : chaque changement repousse l'échéance de 5 s ; un scan déjà en cours (verrou `scan_lock`) = retenté au calme suivant. Fil endormi sur le canal de `notify` quand rien ne bouge ; dossier absent ou erreur = message console. Liste des dossiers relue après chaque scan. Retour sur la fenêtre (`Focused`) plus de 5 min après le dernier scan = rescan (GOG, Ubisoft, Rockstar, Xbox, lus dans le registre). Même chemin que `scan_library` (`rescan` dans `lib.rs`), puis événement `library-changed` : `{ added, removed, scan }` (titres hors jeux masqués, `ScanResult` complet) ; le front remplace la bibliothèque sans spinner et affiche « Nouveau jeu : Hades », « 3 nouveaux jeux » ou « Jeu retiré : Portal ». `library::scan` vide le cache de 10 s de `local::candidates`.
- `src-tauri/src/store.rs` : préférences (favoris, masqués, outils ré-affichés, dernier lancement Ludex, temps mesuré par Ludex en secondes dans `playtime`, jeux manuels `manual`, exécutables choisis `exes`, titres choisis `titles`, réglages `settings` : `keepInTray`, `launchAtStartup`, `trayHintShown`, `savesDir` (dossier des copies, absent = défaut), `autoSaves` (vrai par défaut)) dans `user-data.json` du dossier de données de l'app (`%APPDATA%/com.ludex.app`), champs absents = vides.
- **Jeux ajoutés à la main** (`src-tauri/src/library/manual.rs`) : le sélecteur de fichier natif (crate `tauri-plugin-dialog`, appelée seulement depuis Rust, aucune permission `dialog` côté front) est ouvert par la commande, filtre `.exe` (ni `.lnk` ni `.url`) ; le chemin ne passe jamais par le front. `check_exe` : chemin absolu, extension `.exe`, fichier existant, en-tête `MZ` + `PE\0\0`. `add_game` : titre = ProductName sinon dossier du jeu (dossiers `bin`, `x64`, `Binaries`, `Win64`… remontés) ou nom de l'exe, refus si un jeu lance déjà cet exe ou si l'exe est dans le dossier d'un jeu « Autres » détecté (« Changer l'exécutable » à la place). Stockage `manual: [{ id, exe, title, args }]`, id `other:manual-<FNV du chemin>` fixé à l'ajout (ne suit pas un changement d'exe), `Platform::Other`, `Game.manual` = vrai, `install_dir` = dossier du jeu (suivi des sessions), icône de l'exe, jaquette par `art.rs`. Exe disparu = jeu écarté du scan mais gardé : il revient avec son id (et son temps) quand le fichier réapparaît (disque rebranché). `change_executable(id)` : jeux « Autres » seulement, sélecteur ouvert dans le dossier du jeu ; jeu manuel = `exe` remplacé, jeu détecté = `exes[id]`, exe obligatoirement dans son dossier, ignoré au scan s'il disparaît. `rename_game(id, title)` : tout jeu, `clean_title` (contrôles et caractères invisibles retirés, espaces regroupés, 80 caractères), vide = titre d'origine ; jeu manuel = son `title`, sinon `titles[id]`. `remove_game(id)` : jeux manuels seulement (favori et masqué effacés, temps et historique gardés). `UserData::customize` applique tout dans `rescan`, avant jaquettes et préférences ; un jeu détecté qui lance le même exe qu'un jeu manuel s'efface. Chaque commande attend `scan_lock`, enregistre, rescanne et renvoie `{ id, title, scan }` (`remove_game` : le `ScanResult`).
- **Zone de notification** (`src-tauri/src/tray.rs`, fonction `tray-icon` de Tauri, tout côté Rust, pas d'écran Paramètres) : icône de l'app, info-bulle « Ludex », clic gauche = fenêtre affichée, restaurée et au premier plan (`show_main`). Menu (clic droit) : 5 jeux récents (même logique que `recentGames` du front : non masqués, `lastPlayed` > 0, plus récent d'abord puis titre sans ®/™ ni accents ; `&` doublé, titre coupé à 48 caractères), lancés par `launch` comme `launch_game` (même suivi, puis événement `tray-launch` `{ id, title, lastPlayed, error }` pour le front, fenêtre affichée en cas d'erreur) ; « Ouvrir Ludex », « Lancer avec Windows » et « Garder Ludex dans la zone de notification à la fermeture » (cases à cocher), « Quitter » (quitte vraiment). Menu décrit par des `tray::Entry` (testés), reconstruit après un scan, un lancement ou un masquage seulement s'il change (`AppState.tray_menu`), toujours après un clic sur une case.
- **Fermeture** : `keepInTray` actif par défaut (Ludex en fond continue de mesurer le temps des jeux Epic, Ubisoft, Rockstar, Xbox, Riot ; « Quitter » reste à un clic droit). Fermer la fenêtre la cache (`CloseRequested` empêché). Première fois (`trayHintShown`) : événement `tray-hint`, toast d'explication côté front, fenêtre cachée 3,2 s plus tard (annulé si elle est ré-affichée entre-temps).
- **Lancement avec Windows** : plugin `tauri-plugin-autostart` utilisé depuis Rust seulement (aucune permission au front), clé `Run` du registre utilisateur, argument `--minimized`. Désactivé par défaut ; l'état du registre fait foi pour la case et recopié dans `launchAtStartup` au démarrage. Fenêtre créée cachée (`visible: false`) puis affichée dans `setup` sauf avec `--minimized`.
- **Instance unique** : plugin `tauri-plugin-single-instance` enregistré en premier ; relancer Ludex affiche la fenêtre existante. Une instance de Ludex qui tourne déjà empêche donc d'en lancer une seconde, `tauri dev` compris.
- **Temps de jeu** (`Game.playtime_minutes` + `playtime_source` : `launcher` ou `ludex`, jamais additionnés ; `None` = inconnu) :
  - Steam : `userdata/<steamid3>/config/localconfig.vdf`, `UserLocalConfigStore > Software > Valve > Steam > apps > <appid>` (`Playtime` en minutes, `LastPlayed`). Compte : `config/loginusers.vdf`, `MostRecent` = 1 sinon `timestamp` le plus récent (le Steam actuel n'écrit plus `MostRecent`), steamid3 = SteamID64 − 76561197960265728 ; repli sur le `localconfig.vdf` le plus récent de `userdata`. Appli absente du fichier = 0 min.
  - GOG : base de Galaxy `ProgramData\GOG.com\Galaxy\storage\galaxy-2.0.db` (SQLite via `rusqlite` `bundled`, lecture seule), tables `GameTimes` (`releaseKey` = `gog_<id>`, `minutesInGame`) et `LastPlayedDates`. Seulement si le jeu est lancé par Galaxy.
  - Epic, Ubisoft, Rockstar, Xbox, Riot : aucune donnée locale fiable (fichiers chiffrés ou temps côté serveur), donc mesure par Ludex.
  - `src-tauri/src/session.rs` : mesure par Ludex. `Tracker` = un fil qui dort sans session ; après `launch_game`, relevé toutes les 5 s (crate `sysinfo`, chemins d'exécutables mis en cache) des processus situés sous le dossier du jeu (plus `%LOCALAPPDATA%\Packages\<famille>` pour Xbox ; racines trop larges refusées). Détection jusqu'à 10 min après le lancement, absence tolérée 5 min tant que la session fait moins d'une minute (lanceur intermédiaire type `PlayGTAV.exe`), 30 s ensuite. Écart de plus de 20 s entre deux relevés (veille) non compté, sessions de moins d'une minute ignorées, plafond 24 h. Cumul enregistré chaque minute. Steam et GOG Galaxy (`launcher_tracks_playtime`) sont suivis pour « En jeu » mais jamais cumulés.
  - `src-tauri/src/history.rs` : historique dans `sessions.json` (dossier de données de l'app, une session par ligne : `{ gameId, start, secs, launcher }`, secondes Unix et secondes de jeu, `launcher` = Steam ou Galaxy, temps de référence du launcher, jamais additionné). Toute session d'une minute au moins y va, réécrit en entier (tmp + rename) à sa fin ; au-delà de 5 000 sessions, la moitié ancienne est fusionnée par jeu et par jour UTC, puis les plus anciennes retirées. Sessions en cours dans `session-en-cours.json` (dossiers surveillés, début, dernier relevé, secondes mesurées et déjà cumulées), réécrit à chaque relevé qui change, supprimé quand rien ne tourne. Reprise : au démarrage, `Tracker::resume` (après la mise en place de l'état) relit ce fichier ; si un processus du jeu démarré avant le dernier relevé tourne encore, la session reprend (« En jeu », cumul qui continue) ; sinon elle est close au dernier relevé (historique + reste du cumul). PC redémarré depuis = close directement. Ordre d'écriture : historique, sessions en cours, puis cumul : un arrêt entre deux écritures perd au plus un relevé, jamais de double compte.
- **Succès Steam** (`achievements.rs`, `Game.achievements` = `{ unlocked, total, lastUnlocked }`, `None` = pas de succès ou pas de fichier) : `appcache/stats/`, compte = dossier `userdata` du `localconfig.vdf` retenu. `UserGameStatsSchema_<appid>.bin` : `<appid> > stats > <id> > bits > <n° de bit 0-31>` (type `ACHIEVEMENTS`), total = nombre d'entrées de `bits` (numéros parfois troués). `UserGameStats_<compte>_<appid>.bin` : `cache > <id> > data` (int32, masque des débloqués) et `AchievementTimes > <n° de bit>` (secondes Unix). Schéma sans fichier de progression = `None`, pas « 0 ». Lu pendant le scan Steam.
- **État d'installation** (`Game.install_state`, sérialisé `{ kind, progress? }` : `ready`, `update_required`, `queued`, `updating` et `paused` avec `progress` en % ou `null`, `incomplete` ; `ready` par défaut et hors Steam/Epic). Le bouton Jouer reste actif, le launcher finit le travail au lancement. Steam : bits de `StateFlags` (`EAppState`, liste en tête de `steam.rs`, source SteamKit et crate `game-scanner`) : 512 pause, 256 ou téléchargement/mise en place/vérification… en cours, 1024 seul en file, 32/128 fichiers manquants ou corrompus = incomplet, 2 mise à jour requise ; progression = `BytesDownloaded` / `BytesToDownload`. Jeu listé si bit 4, ou en cours de mise à jour avec un `buildid` connu (première installation écartée). `TargetBuildID` et `ScheduledAutoUpdate` non lus. Epic : `bIsIncompleteInstall` (gardé seulement si `LaunchExecutable` existe déjà, sinon première installation écartée) ou `bNeedsValidation` = `incomplete` ; les mises à jour Epic ne sont pas dans les manifestes. Front : mention `.live.is-pending` (couleur `--lx-warning`) sur la carte à la place de la méta, et dans la fiche à côté de Jouer (`installBadge` et `installNote` de `format.ts`).
- Steam fournit `LastPlayed` et `SizeOnDisk`, Epic `InstallSize`. Images Steam : d'abord `appcache/librarycache/<appid>/` (à plat ou dans des sous-dossiers hachés, jaquette `library_600x900` ou `library_capsule`), sinon le CDN. Les outils (Wallpaper Engine, `* Editor`, `* Dedicated Server`…) sont `is_tool` : masqués par défaut, jamais exclus.
- **Sécurité** : le front n'envoie qu'un id de jeu. La commande de lancement et le dossier sont reconstruits côté Rust depuis l'état. Ne jamais exposer de commande qui prend un chemin ou une URI arbitraire venant du front. CSP stricte dans `tauri.conf.json` (`csp` et `devCsp`, appliquée seulement en build : `npx tauri build --no-bundle` pour la tester) ; toute nouvelle origine d'image va dans `img-src`. Le front n'a que `core:default` comme permission.
- **Installeur et mises à jour** : NSIS seul (`bundle.targets`), installation par utilisateur sans droits admin (`installMode: currentUser`, `%LOCALAPPDATA%\Ludex`), installeur en français, raccourci menu Démarrer par défaut. `src-tauri/src/update.rs` (plugin `tauri-plugin-updater`) : 8 s après l'ouverture puis toutes les 12 h tant que rien n'est trouvé, lecture de `plugins.updater.endpoints` (`latest.json` de la dernière release GitHub) ; erreur (hors ligne, pas de release) = message console seulement ; désactivé en debug (`tauri dev`, `cargo test`). Trouvée : gardée dans `PendingUpdate`, événement `update-available` `{ version, currentVersion, notes }`. Commandes sans argument : `available_update` (après un rechargement du front), `install_update` (téléchargement, signature vérifiée contre `plugins.updater.pubkey`, puis l'installeur NSIS en mode `passive` ferme Ludex et le relance). Front : toast « Ludex x.y.z est disponible » avec « Installer et relancer », puis bouton turquoise dans la barre du haut tant que la mise à jour attend. Aucune permission de plugin côté front, rien dans la CSP (tout passe par Rust). `tauri-plugin-process` inutile : la relance est faite par l'installeur (`AppHandle::restart` hors Windows).
- **Clé des mises à jour** : clé privée hors du dépôt, `%USERPROFILE%\.tauri\ludex-updater.key` (sans mot de passe), clé publique dans `tauri.conf.json`. Perdre la clé privée = plus aucune mise à jour possible pour les versions installées (il faudrait réinstaller à la main) : la sauvegarder. Ne jamais la committer.
- **Signature du code (Authenticode)** : aucune pour l'instant. Effet : SmartScreen affiche « Windows a protégé votre ordinateur » au premier lancement de l'installeur (« Informations complémentaires » puis « Exécuter quand même »), avertissement qui s'estompe avec la réputation du fichier. Options : Azure Trusted Signing (le moins cher, ~10 $/mois, conditions d'éligibilité à vérifier pour un particulier hors États-Unis/Canada, `signCommand` avec `trusted-signing-cli`), certificat OV ou EV (quelques centaines d'euros par an, clé matérielle ou HSM cloud obligatoire ; ni l'un ni l'autre ne supprime d'emblée l'avertissement, la réputation se construit). Brancher via `bundle.windows.certificateThumbprint` + `digestAlgorithm` + `timestampUrl` (certificat installé) ou `bundle.windows.signCommand` (outil externe, `%1` = fichier), puis ajouter les secrets au workflow. Indépendant de la clé des mises à jour.
- `src/lib/api.ts` : types et appels `invoke`. `src/lib/color.ts` : couleur d'ambiance extraite de la jaquette (fallback : hash du titre).
- `src/lib/library.ts` : filtres, tri (Récents, Plus joués, A → Z, Taille), récents, préférences d'affichage (localStorage). `src/lib/format.ts` : dates relatives, tailles, temps de jeu (`formatPlaytime` : « 45 min », « 2,5 h », « 1 240 h », « Jamais joué », « Non mesuré »), recherche.
- `src/components/` : GameCard, LibraryGrid (colonnes mesurées, insère la fiche sous la rangée), GameStrip (fiche dépliable, ligne « genres · studio · année » avec développeurs, éditeurs et date au survol, description sur deux lignes, stat « Temps de jeu » avec sa provenance au survol, stat « Succès » si connue avec le dernier déblocage au survol, « Dernière session » avec la durée tirée de `game_history` ; actions Changer l'exécutable pour « Autres », Renommer avec un champ sur place : Entrée valide, Échap ou clic ailleurs annule, Retirer pour un jeu manuel), ResumeRow, Art et Logo, Cover, States, Icons, SavesPanel (emplacements trouvés, copies, « Sauvegarder maintenant », « Restaurer » confirmé sur place, relu sur `saves-backup`), utilisé replié (« Sauvegardes », lu à l'ouverture) dans GameStrip et dans SavesPage (page autonome : jeux avec sauvegardes ou copies, dossier des copies, case de la copie automatique ; pas encore branchée dans `App.tsx`). Mention `.live` « En jeu » sur la carte, la tuile et la fiche.
- `src/App.tsx` : écran unique « Focus » : grand champ de recherche, bouton « Ajouter un jeu » à côté du rescan (et dans l'état vide), Reprendre, filtres et tri, grille, barre de raccourcis (taper n'importe où, flèches, Entrée, Espace, Échap, Ctrl+D, Ctrl+K, Ctrl+N ajouter, F5). Manette (`src/lib/gamepad.ts`, Gamepad API, ignorée quand Ludex n'a pas le focus) : croix ou stick naviguer, A jouer, X fiche, Y favori, B fermer, LB/RB filtre, LT/RT tri ; la barre du bas montre ces boutons après une action à la manette. Écoute `game-session` (ensemble `playing`, temps mis à jour en direct) et rescanne en silence 10 s après la fin d'une partie. Écoute aussi `tray-launch` (date du lancement, toast d'erreur) et `tray-hint` (toast de la première fermeture).

## Design system

- Tokens dans `src/styles/tokens.css` (préfixe `--lx-*`), styles dans `src/styles/app.css`.
- Logo : une touche de clavier turquoise avec le triangle « Jouer » (`assets/logo/ludex-mark.svg`, version avec le nom `ludex-lockup.svg`, composant `LudexMark`). Icônes de l'app régénérées par `npx tauri icon assets/logo/ludex-mark.svg` (supprimer ensuite `icons/android` et `icons/ios`).
- Palette validée : base monochrome (#0B0B0B, #1A1A1A, #242424, #333333, blanc) + accent turquoise #14B8A6. Thème clair via `[data-theme="light"]`. D'autres thèmes viendront plus tard : toujours passer par les tokens, jamais de couleur en dur.
- `--lx-ambient` : couleur dérivée du jeu sélectionné, réservée au contour de sélection. Bouton Jouer en blanc cassé (`--lx-text` sur `--lx-bg`).
- Passe unslop appliquée : grille de 4px, icônes 18px trait 1.5, graisses 400 à 600, pas de majuscules espacées, chiffres tabulaires, rayons s/m/l = 8/10/12, une seule courbe `--lx-ease`, survol sans déplacement (contour ou voile qui s'éclaircit), léger `scale` au clic.
