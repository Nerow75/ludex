# Ludex

Launcher hub pour Windows : détecte les jeux installés de tous les launchers (Steam, Epic, Riot pour l'instant) et les lance depuis une seule interface. Objectif : plus moderne et plus beau que Playnite ou GOG Galaxy.

## Stack

- Tauri 2 (Rust, edition 2024) dans `src-tauri/`
- React 19 + TypeScript + Vite dans `src/`
- Polices embarquées via @fontsource-variable : Geist (interface), Geist Mono (chiffres, méta, touches)

## Commandes

- `npm run tauri dev` : lance l'app
- `npx tsc --noEmit`, `npm test` puis `npm run build` : vérif front
- `npm test` : tests du front (Vitest, fonctions pures de `src/lib/`) ; `npx vitest` pour les relancer à chaque modification
- `cd src-tauri && cargo test` : tests Rust
- `cd src-tauri && cargo test scan_this_pc -- --ignored --nocapture` : scan réel du PC (avec temps de jeu, les 5 jeux les plus joués, les succès Steam et les jeux pas prêts : mise à jour, téléchargement)
- `cd src-tauri && cargo test achievements_this_pc -- --ignored --nocapture` : coût des succès dans le scan Steam
- `cd src-tauri && cargo test showcase_this_pc -- --ignored --nocapture` : vitrine réelle de ce PC (total, jeux à 100 %, top 10 des plus rares, derniers déblocages), pourcentages mondiaux demandés à Steam avec un cache dans `%TEMP%\ludex-showcase-this-pc` (jamais le dossier de l'app)
- `cd src-tauri && cargo test processes_this_pc -- --ignored --nocapture` : relevé réel des processus, jeux de la bibliothèque déjà ouverts
- `cd src-tauri && cargo test images_this_pc -- --ignored --nocapture` : scan réel puis téléchargement des images manquantes dans `%TEMP%\ludex-images-this-pc` (jamais le dossier de l'app)
- `cd src-tauri && cargo test visuals_this_pc -- --ignored --nocapture` : visuels des jeux hors Steam (images locales des lanceurs, puis Steam puis Microsoft Store pour ceux sans jaquette, images du Store téléchargées en mémoire avec leurs dimensions), sans lire ni écrire les caches de l'app
- `cd src-tauri && cargo test details_this_pc -- --ignored --nocapture` : fiches réelles (genres, tags, ambiances, manette, studio, année) de la bibliothèque, avec les tags les plus fréquents et la répartition des ambiances, sans toucher aux caches de l'app
- `cd src-tauri && cargo test hltb_this_pc -- --ignored --nocapture` : durées de vie HowLongToBeat réelles de la bibliothèque (titres et années tirés des caches de jaquettes et de fiches, lus sans les modifier), 150 requêtes au plus, cache dans un dossier temporaire supprimé à la fin (~2 min, 1,2 s entre deux requêtes)
- `cd src-tauri && cargo test watched_this_pc -- --ignored --nocapture` : dossiers surveillés sur ce PC
- `cd src-tauri && cargo test diagnostic_this_pc -- --ignored --nocapture` : rapport de diagnostic réel de ce PC (scan, emplacements lus, jeux écartés, versions), anonymisé comme « Copier le rapport », lecture seule (jamais `user-data.json` ni les caches de l'app)
- `cd src-tauri && cargo test jump_list_this_pc -- --ignored --nocapture` : pose une vraie Jump List sous un AppID d'essai (`com.ludex.essai-jump-list`, jamais celui de Ludex) puis l'efface
- `cd src-tauri && cargo test screenshots_this_pc -- --ignored --nocapture` : captures d'écran réelles (Steam, Xbox Game Bar), jeu par jeu, appids Steam sans jeu, temps du relevé
- `cd src-tauri && cargo test storage_this_pc -- --ignored --nocapture` : disques, place des jeux par launcher, mesure réelle des dossiers (cache temporaire, préférences lues seulement) et jeux à désinstaller
- `cd src-tauri && cargo test steam_collections_this_pc -- --ignored --nocapture` : collections Steam de ce PC (lecture seule)
- `cd src-tauri && cargo test watches_a_steam_library -- --ignored --nocapture` : surveillance réelle d'un faux `steamapps` (anti-rebond, progression en direct d'une mise à jour, ~20 s)
- `cd src-tauri && cargo test saves_this_pc -- --ignored --nocapture` : base des sauvegardes téléchargée dans `%TEMP%\ludex-saves-this-pc`, puis jeux de la bibliothèque dont des sauvegardes sont trouvées (emplacements, tailles), sans rien copier ni toucher aux dossiers de l'app
- `cd src-tauri && cargo test journal_this_pc -- --ignored --nocapture` : journal réel de ce PC (lecture seule : `sessions.json` de l'app, succès Steam, captures), toutes les pages, jours actifs et date la plus ancienne
- `cd src-tauri && cargo test news_this_pc -- --ignored --nocapture` : actualités réelles (annonces Steam) des 40 premiers jeux de ce PC qui ont un appid, 0,5 s entre deux requêtes (~35 s), cache et annonces converties (`annonces.json`, à relire à la main) dans `%TEMP%\ludex-news-this-pc` (jamais le dossier de l'app), puis les 10 annonces les plus récentes
- `cd src-tauri && cargo clippy --all-targets` : doit rester sans avertissement
- Écran de premier lancement sans toucher aux vraies données : `$env:LUDEX_WELCOME = "1"` puis `npm run tauri dev` (debug), ou en release `npx tauri build --no-bundle --features welcome-preview` puis `src-tauri/target/release/ludex.exe` lancé avec la même variable (jamais cette fonction dans une build publiée). Fermer toute autre instance de Ludex avant (instance unique).
- Installeur local (PowerShell) : `$env:TAURI_SIGNING_PRIVATE_KEY = "$env:USERPROFILE\.tauri\ludex-updater.key"; $env:CI = "true"; npx tauri build` (`CI` = mot de passe vide, sans invite). Produit `src-tauri/target/release/bundle/nsis/Ludex_<version>_x64-setup.exe` et son `.sig`. Sans la clé, la build échoue (`createUpdaterArtifacts`) : `npx tauri build --no-bundle` pour tester la CSP seulement.
- CI : `.github/workflows/verif.yml` à chaque push (hors tags `v*`) et pull request, sous `windows-latest` : `npm ci`, `tsc`, `npm test`, `npm run build`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (tests `--ignored` jamais lancés).
- Release : monter la version dans `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` et `package.json` (les trois identiques), committer, puis `git tag v<version>` et `git push origin v<version>` : le workflow `.github/workflows/release.yml` construit et publie.

## Architecture

- `src-tauri/src/library/` : une source par launcher (`steam.rs`, `epic.rs`, `gog.rs`, `ubisoft.rs`, `ea.rs`, `battlenet.rs`, `rockstar.rs`, `xbox.rs`, `riot.rs`, puis `local.rs` pour « Autres »), lecture de fichiers locaux et du registre uniquement, aucune connexion à un compte. `vdf.rs` parse le format texte de Valve, `kvbin.rs` le KeyValues binaire (chaînes empruntées au fichier, `None` si tronqué ou type inconnu). `mod.rs` définit `Game`, `Launch`, `ScanResult`, les utilitaires `reg` (registre en lecture) et `xml_attr`, et agrège les sources dans l'ordre de priorité : `Ok(None)` = launcher absent, `Ok(Some(vec![]))` = installé sans jeu ; un jeu dont le dossier est déjà vu par une source précédente (même dossier, parent ou sous-dossier) est écarté.
- Sources : GOG (registre `GOG.com\Games`, lancement par Galaxy ou l'exe), Ubisoft (registre `Ubisoft\Launcher\Installs`, `uplay://launch/<id>/0`), Rockstar (registre `Rockstar Games`, exe `Play*.exe`, images Steam via une table titre → appid), Xbox (registre des paquets MSIX, jeu = `MicrosoftGame.config` à la racine, `explorer.exe shell:AppsFolder\<famille>!<app>`, visuel = écran de démarrage local). `Launch::Exec` part du dossier de l'exécutable.
- Dossiers de jeux (`local.rs`) : sous-dossiers des dossiers « Jeux » / « Games » à la racine des lecteurs (un « Jeux Epic » dedans est lu aussi, `XboxGames` exclu) et emplacements de la désinstallation Windows qui contiennent un moteur (Unity, Unreal, Steamworks), liste gardée 10 s pour un même scan. Chaque dossier est rangé : `.product.db` + `.build.info` = Battle.net (code produit → `battlenet://<code>` si le client est là, sinon l'exe), `__Installer\installerdata.xml` = EA (contentID, titre, exe non « trial » lancé directement), sinon « Autres » : exe choisi par score (nom proche du dossier, profondeur ≤ 3, taille, listes d'exclusion installeurs/utilitaires/anti-triche), titre = ProductName de l'exe (crate `pelite`) sinon dossier ou nom de l'exe ; launchers installés écartés, doublons de titre écartés. Plus des emplacements fixes : FiveM, RedM, RAGE MP, Roblox, jeux Ankama (lancés par l'Ankama Launcher), Pokeisland. Images du lanceur reprises (`set_local_art`, servies par le protocole `ludex`) : jeux Ankama = `%APPDATA%\zaap\repositories\production\<jeu>\<version>\data` du dossier `<Jeu>-<version>` (`ankama_art` : `cover.jpg` jaquette, `home_cover.jpg` fond, `logo.png`, image absente prise dans `main`, noms alphanumériques seulement), FiveM et RedM = `<nom>.app\citizen\resources\background_main.jpg` en image de fond (`cfx_art`).
- `src-tauri/src/lib.rs` : commandes Tauri `scan_library`, `launch_game` (renvoie l'heure du lancement et démarre le suivi de session), `open_install_dir`, `set_favorite`, `set_hidden`, `game_sessions` (sessions en cours), `game_history` (sessions terminées d'un jeu, la plus récente d'abord), `add_game`, `change_executable`, `rename_game`, `remove_game` (voir « Jeux ajoutés à la main »), `choose_cover`, `reset_cover` (voir « Jaquettes perso »), `game_screenshots`, `all_screenshots`, `show_screenshot` (voir « Captures d'écran »), `game_saves`, `backup_saves`, `restore_saves`, `choose_saves_dir`, `set_auto_saves`, `saves_overview` (voir « Sauvegardes »). `set_status`, `set_note`, `collections`, `create_collection`, `rename_collection`, `delete_collection`, `set_in_collection` (voir « Progression et collections »). `set_launch_args` (voir « Options de lancement »). `quick_games`, `hide_quick` (voir « Recherche rapide »). `welcome`, `welcome_done`, `welcome_again` (voir « Premier lancement »). `settings`, `set_theme`, `set_quick_shortcut`, `pause_quick_shortcut`, `set_launch_at_startup`, `set_keep_in_tray`, `set_source_enabled`, `show_all_hidden`, `check_update` (voir « Paramètres »). `create_shortcut` (voir « Lien ludex://, raccourci et Jump List »). `diagnostic` (voir « Diagnostic »). `export_data`, `import_data`, `cancel_import`, `apply_import` (voir « Export et import des données »). `game_news`, `open_news` (voir « Actualités »). Jeux scannés, préférences et `Tracker` gardés dans `AppState`. Événement `game-session` : `{ id, phase: detecting|running|ended, playtimeMinutes, playtimeSource }`, le temps n'étant rempli que quand Ludex vient d'ajouter du temps. Protocole `ludex` (`http://ludex.localhost/<plateforme>/<id>/<cover|hero|logo|icon>` sous Windows) : sert les images locales d'un jeu de l'état (`Game.local_art`, jamais sérialisé ; `icon` = icône extraite de l'exe par `local::exe_icon`, PNG ou .ico), type lu dans la signature, `Cache-Control: no-cache` + `ETag` (taille, date) avec réponse 304. Événement `game-art` : `{ id, coverUrl, heroUrl, logoUrl, customArt }`, envoyé quand une jaquette vient d'être trouvée en ligne, qu'une image vient d'entrer dans le cache disque ou qu'une jaquette perso est choisie ou retirée.
- **Captures d'écran** (`src-tauri/src/screenshots.rs`, lecture seule) : Steam = `userdata/<compte>/760/remote/<appid>/screenshots/*.jpg|png` (compte = celui de `localconfig.vdf`, `steam::account_dir`) et miniatures `screenshots/thumbnails/<même nom>`, appid rattaché au jeu dont `steam_appid` correspond (jeu Steam d'abord, puis Rockstar ou jaquette retrouvée) ; Xbox Game Bar = dossier connu « Captures » (`User Shell Folders\{EDC0FE71-98D8-4F4A-B920-C8DC133CB165}`, `%VAR%` développées) sinon `My Video\Captures`, fichiers `.png`, `.jpg`, `.mp4` à la racine (`.jxr` HDR ignorés), titre = nom sans la date finale (`capture_title` : jetons avec chiffres et séparateur `-_.:`, AM/PM, trois au plus), jeu = mêmes mots (`match_game`, ®/™ et ponctuation ignorés) ou mots du plus court (deux au moins) au début de l'autre, le plus long l'emporte. Sans jeu (appid Steam désinstallé, titre inconnu) = « Autres captures » (`gameId` nul, `steamAppid` gardé pour l'affichage). `Shot` : `key` (FNV du chemin en minuscules, 16 hex), date = modification du fichier, taille, dimensions lues dans l'en-tête PNG/JPEG (SOF), `video`, `thumbUrl`/`url`. Commandes : `game_screenshots(id)` (la plus récente d'abord, seul le dossier de l'appid du jeu lu), `all_screenshots()` (groupes par jeu, le plus récent d'abord, « Autres captures » en dernier), `show_screenshot(id | null, key)` (nouveau relevé côté Rust, puis `reveal_item_in_dir` : Explorateur avec le fichier sélectionné). Service : `ludex` `/capture/<key>/<thumb|full>`, seulement pour une empreinte d'un relevé déjà envoyé (`AppState.shots`, `Index`, vidé à chaque `all_screenshots` ou si les dossiers changent) et un fichier toujours dans un dossier connu (`allowed` : chemin résolu, `<racine Steam>\<appid>\screenshots` ou son `thumbnails` ou racine de « Captures », extension permise) ; images avec `ETag` comme les jaquettes, vidéos par morceaux de 2 Mo (`Range`, 206, 416). CSP : `media-src` ajouté (`ludex:` et `http://ludex.localhost`) pour les vidéos. Front : `ScreenshotViewer.tsx` (`ShotTile` et visionneuse plein écran en portail : flèches, Échap, « Ouvrir le dossier » ; touches arrêtées en phase de capture, aucun raccourci global pendant qu'elle est ouverte), `ScreenshotsPage.tsx` (page autonome, groupes, relecture, `onOpenGame` facultatif, section « Captures » de `SECTIONS`), section « Captures » de `GameStrip` (6 vignettes, « +N » sur la dernière, cachée sans capture, relue à la fin d'une partie).
- **Cache disque des images** (`src-tauri/src/images.rs`) : jaquette, image de fond et logo distants (CDN Steam) gardés dans `<données>/images/<plateforme>/<id nettoyé>/<cover|hero|logo>.<jpg|png|webp>`, index `images/index.json` (URL d'origine de chaque fichier, 404 notées, dernière présence de chaque jeu). Au scan, `ImageCache::apply` en dernier : une image distante déjà en cache (même URL d'origine) passe sur `local_art` + URL `ludex` ; les images locales du launcher restent prioritaires et ne sont jamais copiées. Fil `resolve_images` après chaque scan et après `resolve_art` (`images_busy`) : 4 téléchargements à la fois, jaquettes d'abord, arrêt après 3 erreurs réseau de suite, puis `game-art` par image. Règles : téléchargement seulement depuis les URL de l'état, hôtes en liste blanche stricte (`cdn.cloudflare.steamstatic.com`, `shared.akamai.steamstatic.com` sans requête ; `store-images.s-microsoft.com` seulement sous `image/` avec au plus `?w=<n>` ou `?w=<n>&h=<n>` ; jamais de `..`), redirections jamais suivies, 8 Mo au plus, JPEG/PNG/WebP vérifiés par signature, écriture tmp + renommage, id nettoyé (`clean_id` : ASCII minuscule, empreinte FNV si modifié, noms réservés Windows évités). 404 (ou 403, 410, redirection, image invalide) notée et redemandée après 7 jours. Purge : dossier d'un jeu absent de la bibliothèque depuis 60 jours supprimé (jamais `images/custom/`), pas de plafond global (la taille suit la bibliothèque). Écriture commune `images::store(dir, kind, octets, ext)`. Les origines CDN restent dans `img-src` pour le premier affichage. Événement `game-details` : `{ id, details }`, envoyé quand une fiche arrive ou change.
- **Jaquettes hors Steam** (`src-tauri/src/art.rs`) : pour chaque jeu sans jaquette (hors Steam), titre cherché dans la recherche publique de la boutique Steam (`storesearch`, aucun compte, crate `ureq`), correspondance stricte (`same_game` : égalité, nom Steam qui finit par le titre, faute de frappe sans changer les nombres), table `DELISTED` pour les jeux retirés de la vente (FC, FIFA, Football Manager…). Chemins exacts des images lus dans `IStoreBrowseService/GetItems` (jeux récents : chemins hachés sur `shared.akamai.steamstatic.com`), sinon adresse classique du CDN. Cache `art-cache.json` (dossier de données) : trouvé = gardé, introuvable = recherché après 30 jours, `MATCHING_VERSION` à augmenter pour tout relancer. Recherche dans un fil après chaque scan, 350 ms entre deux titres. Absent de Steam : catalogue public du Microsoft Store, sans clé ni compte (`store_search` : `displaycatalog.mp.microsoft.com/v7.0/productFamilies/autosuggest` marché FR, premier produit `Type` = `Game` dont le nom correspond, puis `v7.0/products?bigIds=<id>`), correspondance plus stricte encore (`same_store_game` : égalité aux symboles, casse, mention d'édition et de plateforme finale près, « Roblox - Windows » = Roblox, aucune faute ; « StarCraft II : Collection de campagnes » refusé), id produit validé (12 majuscules ou chiffres), nom du produit revérifié dans la fiche. Images : `Poster` (sinon `BrandedKeyArt`, plus haute que large) en jaquette `?w=600` (600 × 900), `SuperHeroArt` (plus large que haute) en fond `?w=1920` ; pas de logo (le Store n'a que des icônes carrées). Seul le nom de chaque image est gardé (`StoreArt` dans l'entrée du cache, `store_image` : préfixe `//store-images.s-microsoft.com/image/`, lettres, chiffres, `.`, `-`), URL reconstruite par Ludex ; un fond déjà posé (launcher) n'est pas remplacé ; pas d'appid, donc ni fiche ni durée de vie. `MATCHING_VERSION` 4. Une erreur réseau du Store arrête la recherche comme celle de Steam. Origine `https://store-images.s-microsoft.com` dans `img-src` (`csp` et `devCsp`). Sans jaquette : l'icône de l'exe sur la jaquette générée (`iconUrl`). L'appid retenu est gardé dans `Game.steam_appid`.
- **Jaquettes perso** (`src-tauri/src/covers.rs`) : jaquette et image de fond choisies pour n'importe quel jeu. `choose_cover(id, kind)` (`kind` = `cover` | `hero`, enum serde fermée `covers::Kind`) ouvre le sélecteur natif côté Rust (filtre PNG, JPEG, WebP ; aucun chemin ne passe par le front), vérifie le fichier (`check_image` : chemin absolu, extension d'image, 16 Mo au plus, signature, dimensions lues dans l'en-tête PNG/JPEG/WebP entre 16 et 16 384 px ; extension de la copie tirée de la signature), le COPIE dans `<données>/images/custom/<clean_id(id du jeu)>/<cover|hero>.<jpg|png|webp>` (tmp + renommage, `images::store`) : le fichier d'origine n'est jamais relu. Choix gardé dans `user-data.json` (`covers` : `{ <id>: { cover?: { ext, at }, hero?: … } }`, `at` = millisecondes du choix), qui versionne l'URL (`http://ludex.localhost/<plateforme>/<id>/<cover|hero>?v=<at>`, la requête est ignorée par le protocole) pour que la WebView n'affiche pas l'ancienne image. Priorité : image perso > images locales du launcher > cache disque > CDN > jaquette générée ; posée en dernier dans `rescan` (`covers::apply` après `images.apply`) sur `local_art` et l'URL, servie par le protocole `ludex` existant. `Game.custom_art` (`customArt` : types remplacés). L'image remplacée est gardée en mémoire (`AppState.originals`, refait à chaque scan, verrouillé après `games`) : `reset_cover(id, kind)` la rend sans rescan, réapplique `art.rs` et le cache disque, puis relance la recherche de jaquettes et les téléchargements. Une jaquette perso coupe la recherche en ligne (`art::needs_art` faux) et le téléchargement de la jaquette distante. Fichier perso disparu = ignoré au scan. Les deux commandes attendent `scan_lock`, enregistrent puis envoient `game-art` (et renvoient le même contenu ; `choose_cover` : `null` si annulé). Purge (`covers::purge`, dans `tidy_images`) : seul un dossier `custom/` dont le jeu n'est ni dans `covers` ni dans la bibliothèque est supprimé (restes) ; un jeu manuel retiré ou désinstallé garde ses images perso. Front : boutons « Changer la jaquette » et « Changer l'image de fond » de `GameStrip` (après Renommer), « Jaquette d'origine » (ou « Image de fond d'origine », ou les deux) quand une image perso existe, toasts de confirmation.
- **Fiches** (`src-tauri/src/metadata.rs`, `Game.details` : genres, `tags`, `moods`, `controller`, développeurs, éditeurs, `releaseDate` en secondes Unix, description courte) pour tout jeu avec `Game.steam_appid` (Steam, table Rockstar, jeux retrouvés par `art.rs`, jamais sérialisé). API publique `IStoreBrowseService/GetItems` (`include_basic_info`, `include_release`, `include_tag_count` 20, `language` french ; `categories` arrive sans rien demander), 40 appids par requête, 1 s entre deux lots. Les tags n'y sont que des numéros : noms français lus par `IStoreService/GetTagList?language=french` (~450 tags, public, sans clé) avant les fiches, gardés dans le cache (`tagNames`) et relus après 30 jours (ancienne liste gardée si la relecture échoue ; aucune liste = lecture des fiches arrêtée). Le cache garde les données brutes (`Item` : ids des tags par votes décroissants, catégories « joueurs » et « manette », studio, éditeur, date, description) ; `Details` en est tiré à chaque `apply` : genres = étiquettes de genre de `GENRES` (Action, Aventure, Stratégie, RPG…, sans Free-to-play, Accès anticipé ni Indépendant), trois au plus ; tags = dix premiers noms connus (genres compris) ; manette = catégorie 28 `full`, sinon 18 `partial`, sinon `null` ; date = sortie d'origine sinon sortie Steam. Changer `GENRES`, `MAX_TAGS` ou les ambiances ne demande donc pas de relire. Cache `metadata-cache.json` : appid redemandé après 30 jours, une fiche connue n'est jamais effacée par une réponse vide, `CACHE_VERSION` (2 depuis les tags) pour tout relancer. Fil après chaque scan et après la recherche des jaquettes (nouveaux appids), `meta_busy` contre les doublons ; une erreur réseau arrête la lecture.
- **Durée de vie** (`src-tauri/src/hltb.rs`, `Game.hltb` = `{ name, main, plus, full }` en minutes, `null` par durée trop peu notée, `None` tant qu'inconnue) : HowLongToBeat, sans API publique : Ludex fait comme la recherche du site, User-Agent honnête (`Ludex/<version> (lanceur de jeux)`), aucun compte. `GET <point>/init?t=<ms>` donne un jeton (`token`, plus une paire `*key*`/`*val*` reprise en `x-hp-key`/`x-hp-val` si le site en ajoute une), puis `POST <point>` (JSON de la recherche du site, 20 résultats, en-tête `x-auth-token`) ; point d'entrée `/api/search/site` à ce jour. Jeton refusé (403) = redemandé une fois ; point d'entrée disparu (404) = relu une fois dans les scripts Next.js de la page d'accueil (`/_next/static/chunks/*.js`, chemin `/api/…` devant `/init?t=`, 20 scripts au plus) et gardé dans le cache ; toute autre erreur (réseau, 429, 5xx, réponse illisible) arrête la lecture sans rien noter pour les titres restants (« inconnu » jusqu'au scan suivant). Redirections refusées. Réponse lue en `Value` (nombres en chaîne acceptés), `comp_main`, `comp_plus`, `comp_100` en secondes arrondies à la minute. Correspondance stricte (`same_name`) : titre égal au nom ou à un alias (`game_alias`, séparés par des virgules) aux symboles, accents, casse, `&`/and et mention d'édition près (`art::without_edition`), aucune faute de frappe tolérée, nom suivi d'une année « (2005) » compris ; mods et hacks écartés ; puis jeu de base avant DLC, année la plus proche de `Game.details.releaseDate`, puis le plus populaire ; homonyme à plus de 10 ans (`MAX_YEAR_GAP`) écarté. Cache `hltb-cache.json` : clé = titre comparable + `@<année>` si connue, trouvé ou introuvable redemandé après 30 jours, `CACHE_VERSION`. Outils (`is_tool`) jamais cherchés. Fil `resolve_hltb` après les jaquettes et les fiches (attend `art_busy` et `meta_busy`, rappelé à la fin de leurs fils), `hltb_busy`, une requête à la fois, 1,2 s entre deux, enregistré après chaque titre. Événement `game-hltb` : `{ id, hltb }`. Rien dans la CSP (aucune image HLTB). Front : bloc « Durée de vie » de la fiche (`Lifespan` dans `GameStrip`) : Histoire, + Extras, 100 %, barres remplies selon `playtimeMinutes`, « inconnu » par durée absente, temps restant estimé pour l'histoire ; caché sans données.

## Design system

- Tokens dans `src/styles/tokens.css` (préfixe `--lx-*`), styles dans `src/styles/app.css`.
- Logo : une touche de clavier turquoise avec le triangle « Jouer » (`assets/logo/ludex-mark.svg`, version avec le nom `ludex-lockup.svg`, composant `LudexMark`). Icônes de l'app régénérées par `npx tauri icon assets/logo/ludex-mark.svg` (supprimer ensuite `icons/android` et `icons/ios`).
- Palette validée : base monochrome (#0B0B0B, #1A1A1A, #242424, #333333, blanc) + accent turquoise #14B8A6. Thème clair via `[data-theme="light"]`. D'autres thèmes viendront plus tard : toujours passer par les tokens, jamais de couleur en dur.
- Thèmes (`tokens.css`) : sombre par défaut (`:root`), `[data-theme="light"]`, `[data-theme="oled"]` (fond #000, surfaces #0A0A0A et #161616, contours #2A2A2A, aucun gris moyen en grand aplat, turquoise #14B8A6 gardé) et `[data-theme="contrast"]` (sombre, textes AAA : `--lx-text-3` #BDBDBD à 8,8:1 sur `--lx-surface-2`, contours #A3A3A3 à 6,5:1 au moins, turquoise plus lumineux #2DD4BF, texte d'accent #5EEAD4 ; rapports en commentaire). Ce qui ne tient pas dans un token est en fin d'`app.css` : focus de 3 px, contour blanc au survol des boutons sans bordure, état choisi (section, `.seg`) entouré, fondus pleins sous le texte des visuels larges (fiche, « Ce soir », mode canapé), « autres fichiers » du Stockage hachés. Tokens « sur image » communs à tous les thèmes (`--lx-art-base`, `--lx-art-deep`, `--lx-on-art`, `--lx-on-art-2`, `--lx-art-scrim`, `--lx-art-badge`, `--lx-shadow` pour les ombres par `color-mix`) : plus aucune couleur en dur dans `app.css` ni `quick.css`. `--lx-accent-soft` = fond sombre d'une pastille cochée en sombre (texte blanc ; l'ancien #99F6E4 donnait du blanc sur turquoise clair). Contraste de Windows (`forced-colors: active`) : barres, interrupteurs, onglet et section choisis, sélection et focus passent aux couleurs système (`Highlight`, `GrayText`, `CanvasText`).
- `--lx-ambient` : couleur dérivée du jeu sélectionné, réservée au contour de sélection. Bouton Jouer en blanc cassé (`--lx-text` sur `--lx-bg`).
- Passe unslop appliquée : grille de 4px, icônes 18px trait 1.5, graisses 400 à 600, pas de majuscules espacées, chiffres tabulaires, rayons s/m/l = 8/10/12, une seule courbe `--lx-ease`, survol sans déplacement (contour ou voile qui s'éclaircit), léger `scale` au clic.
