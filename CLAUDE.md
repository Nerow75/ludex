# Ludex

Launcher hub pour Windows : détecte les jeux installés de tous les launchers (Steam, Epic, Riot pour l'instant) et les lance depuis une seule interface. Objectif : plus moderne et plus beau que Playnite ou GOG Galaxy.

## Stack

- Tauri 2 (Rust, edition 2024) dans `src-tauri/`
- React 19 + TypeScript + Vite dans `src/`
- Polices embarquées via @fontsource-variable : Geist (interface), Geist Mono (chiffres, méta, touches)

## Commandes

- `npm run tauri dev` : lance l'app
- `npx tsc --noEmit` puis `npm run build` : vérif front
- `cd src-tauri && cargo test` : tests Rust
- `cd src-tauri && cargo test scan_this_pc -- --ignored --nocapture` : scan réel du PC (avec temps de jeu, les 5 jeux les plus joués, les succès Steam et les jeux pas prêts : mise à jour, téléchargement)
- `cd src-tauri && cargo test achievements_this_pc -- --ignored --nocapture` : coût des succès dans le scan Steam
- `cd src-tauri && cargo test showcase_this_pc -- --ignored --nocapture` : vitrine réelle de ce PC (total, jeux à 100 %, top 10 des plus rares, derniers déblocages), pourcentages mondiaux demandés à Steam avec un cache dans `%TEMP%\ludex-showcase-this-pc` (jamais le dossier de l'app)
- `cd src-tauri && cargo test processes_this_pc -- --ignored --nocapture` : relevé réel des processus, jeux de la bibliothèque déjà ouverts
- `cd src-tauri && cargo test images_this_pc -- --ignored --nocapture` : scan réel puis téléchargement des images manquantes dans `%TEMP%\ludex-images-this-pc` (jamais le dossier de l'app)
- `cd src-tauri && cargo test details_this_pc -- --ignored --nocapture` : fiches réelles (genres, tags, ambiances, manette, studio, année) de la bibliothèque, avec les tags les plus fréquents et la répartition des ambiances, sans toucher aux caches de l'app
- `cd src-tauri && cargo test watched_this_pc -- --ignored --nocapture` : dossiers surveillés sur ce PC
- `cd src-tauri && cargo test screenshots_this_pc -- --ignored --nocapture` : captures d'écran réelles (Steam, Xbox Game Bar), jeu par jeu, appids Steam sans jeu, temps du relevé
- `cd src-tauri && cargo test storage_this_pc -- --ignored --nocapture` : disques, place des jeux par launcher, mesure réelle des dossiers (cache temporaire, préférences lues seulement) et jeux à désinstaller
- `cd src-tauri && cargo test steam_collections_this_pc -- --ignored --nocapture` : collections Steam de ce PC (lecture seule)
- `cd src-tauri && cargo test watches_a_steam_library -- --ignored --nocapture` : surveillance réelle d'un faux `steamapps` (anti-rebond, ~13 s)
- `cd src-tauri && cargo test saves_this_pc -- --ignored --nocapture` : base des sauvegardes téléchargée dans `%TEMP%\ludex-saves-this-pc`, puis jeux de la bibliothèque dont des sauvegardes sont trouvées (emplacements, tailles), sans rien copier ni toucher aux dossiers de l'app
- `cd src-tauri && cargo test journal_this_pc -- --ignored --nocapture` : journal réel de ce PC (lecture seule : `sessions.json` de l'app, succès Steam, captures), toutes les pages, jours actifs et date la plus ancienne
- `cd src-tauri && cargo clippy --all-targets` : doit rester sans avertissement
- Installeur local (PowerShell) : `$env:TAURI_SIGNING_PRIVATE_KEY = "$env:USERPROFILE\.tauri\ludex-updater.key"; $env:CI = "true"; npx tauri build` (`CI` = mot de passe vide, sans invite). Produit `src-tauri/target/release/bundle/nsis/Ludex_<version>_x64-setup.exe` et son `.sig`. Sans la clé, la build échoue (`createUpdaterArtifacts`) : `npx tauri build --no-bundle` pour tester la CSP seulement.
- Release : monter la version dans `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` et `package.json` (les trois identiques), committer, puis `git tag v<version>` et `git push origin v<version>` : le workflow `.github/workflows/release.yml` construit et publie.

## Architecture

- `src-tauri/src/library/` : une source par launcher (`steam.rs`, `epic.rs`, `gog.rs`, `ubisoft.rs`, `ea.rs`, `battlenet.rs`, `rockstar.rs`, `xbox.rs`, `riot.rs`, puis `local.rs` pour « Autres »), lecture de fichiers locaux et du registre uniquement, aucune connexion à un compte. `vdf.rs` parse le format texte de Valve, `kvbin.rs` le KeyValues binaire (chaînes empruntées au fichier, `None` si tronqué ou type inconnu). `mod.rs` définit `Game`, `Launch`, `ScanResult`, les utilitaires `reg` (registre en lecture) et `xml_attr`, et agrège les sources dans l'ordre de priorité : `Ok(None)` = launcher absent, `Ok(Some(vec![]))` = installé sans jeu ; un jeu dont le dossier est déjà vu par une source précédente (même dossier, parent ou sous-dossier) est écarté.
- Sources : GOG (registre `GOG.com\Games`, lancement par Galaxy ou l'exe), Ubisoft (registre `Ubisoft\Launcher\Installs`, `uplay://launch/<id>/0`), Rockstar (registre `Rockstar Games`, exe `Play*.exe`, images Steam via une table titre → appid), Xbox (registre des paquets MSIX, jeu = `MicrosoftGame.config` à la racine, `explorer.exe shell:AppsFolder\<famille>!<app>`, visuel = écran de démarrage local). `Launch::Exec` part du dossier de l'exécutable.
- Dossiers de jeux (`local.rs`) : sous-dossiers des dossiers « Jeux » / « Games » à la racine des lecteurs (un « Jeux Epic » dedans est lu aussi, `XboxGames` exclu) et emplacements de la désinstallation Windows qui contiennent un moteur (Unity, Unreal, Steamworks), liste gardée 10 s pour un même scan. Chaque dossier est rangé : `.product.db` + `.build.info` = Battle.net (code produit → `battlenet://<code>` si le client est là, sinon l'exe), `__Installer\installerdata.xml` = EA (contentID, titre, exe non « trial » lancé directement), sinon « Autres » : exe choisi par score (nom proche du dossier, profondeur ≤ 3, taille, listes d'exclusion installeurs/utilitaires/anti-triche), titre = ProductName de l'exe (crate `pelite`) sinon dossier ou nom de l'exe ; launchers installés écartés, doublons de titre écartés. Plus des emplacements fixes : FiveM, RedM, RAGE MP, Roblox, jeux Ankama (lancés par l'Ankama Launcher), Pokeisland.
- `src-tauri/src/lib.rs` : commandes Tauri `scan_library`, `launch_game` (renvoie l'heure du lancement et démarre le suivi de session), `open_install_dir`, `set_favorite`, `set_hidden`, `game_sessions` (sessions en cours), `game_history` (sessions terminées d'un jeu, la plus récente d'abord), `add_game`, `change_executable`, `rename_game`, `remove_game` (voir « Jeux ajoutés à la main »), `choose_cover`, `reset_cover` (voir « Jaquettes perso »), `game_screenshots`, `all_screenshots`, `show_screenshot` (voir « Captures d'écran »), `game_saves`, `backup_saves`, `restore_saves`, `choose_saves_dir`, `set_auto_saves`, `saves_overview` (voir « Sauvegardes »). `set_status`, `set_note`, `collections`, `create_collection`, `rename_collection`, `delete_collection`, `set_in_collection` (voir « Progression et collections »). Jeux scannés, préférences et `Tracker` gardés dans `AppState`. Événement `game-session` : `{ id, phase: detecting|running|ended, playtimeMinutes, playtimeSource }`, le temps n'étant rempli que quand Ludex vient d'ajouter du temps. Protocole `ludex` (`http://ludex.localhost/<plateforme>/<id>/<cover|hero|logo|icon>` sous Windows) : sert les images locales d'un jeu de l'état (`Game.local_art`, jamais sérialisé ; `icon` = icône extraite de l'exe par `local::exe_icon`, PNG ou .ico), type lu dans la signature, `Cache-Control: no-cache` + `ETag` (taille, date) avec réponse 304. Événement `game-art` : `{ id, coverUrl, heroUrl, logoUrl, customArt }`, envoyé quand une jaquette vient d'être trouvée en ligne, qu'une image vient d'entrer dans le cache disque ou qu'une jaquette perso est choisie ou retirée.
- **Captures d'écran** (`src-tauri/src/screenshots.rs`, lecture seule) : Steam = `userdata/<compte>/760/remote/<appid>/screenshots/*.jpg|png` (compte = celui de `localconfig.vdf`, `steam::account_dir`) et miniatures `screenshots/thumbnails/<même nom>`, appid rattaché au jeu dont `steam_appid` correspond (jeu Steam d'abord, puis Rockstar ou jaquette retrouvée) ; Xbox Game Bar = dossier connu « Captures » (`User Shell Folders\{EDC0FE71-98D8-4F4A-B920-C8DC133CB165}`, `%VAR%` développées) sinon `My Video\Captures`, fichiers `.png`, `.jpg`, `.mp4` à la racine (`.jxr` HDR ignorés), titre = nom sans la date finale (`capture_title` : jetons avec chiffres et séparateur `-_.:`, AM/PM, trois au plus), jeu = mêmes mots (`match_game`, ®/™ et ponctuation ignorés) ou mots du plus court (deux au moins) au début de l'autre, le plus long l'emporte. Sans jeu (appid Steam désinstallé, titre inconnu) = « Autres captures » (`gameId` nul, `steamAppid` gardé pour l'affichage). `Shot` : `key` (FNV du chemin en minuscules, 16 hex), date = modification du fichier, taille, dimensions lues dans l'en-tête PNG/JPEG (SOF), `video`, `thumbUrl`/`url`. Commandes : `game_screenshots(id)` (la plus récente d'abord, seul le dossier de l'appid du jeu lu), `all_screenshots()` (groupes par jeu, le plus récent d'abord, « Autres captures » en dernier), `show_screenshot(id | null, key)` (nouveau relevé côté Rust, puis `reveal_item_in_dir` : Explorateur avec le fichier sélectionné). Service : `ludex` `/capture/<key>/<thumb|full>`, seulement pour une empreinte d'un relevé déjà envoyé (`AppState.shots`, `Index`, vidé à chaque `all_screenshots` ou si les dossiers changent) et un fichier toujours dans un dossier connu (`allowed` : chemin résolu, `<racine Steam>\<appid>\screenshots` ou son `thumbnails` ou racine de « Captures », extension permise) ; images avec `ETag` comme les jaquettes, vidéos par morceaux de 2 Mo (`Range`, 206, 416). CSP : `media-src` ajouté (`ludex:` et `http://ludex.localhost`) pour les vidéos. Front : `ScreenshotViewer.tsx` (`ShotTile` et visionneuse plein écran en portail : flèches, Échap, « Ouvrir le dossier » ; touches arrêtées en phase de capture, aucun raccourci global pendant qu'elle est ouverte), `ScreenshotsPage.tsx` (page autonome, groupes, relecture, `onOpenGame` facultatif, section « Captures » de `SECTIONS`), section « Captures » de `GameStrip` (6 vignettes, « +N » sur la dernière, cachée sans capture, relue à la fin d'une partie).
- **Cache disque des images** (`src-tauri/src/images.rs`) : jaquette, image de fond et logo distants (CDN Steam) gardés dans `<données>/images/<plateforme>/<id nettoyé>/<cover|hero|logo>.<jpg|png|webp>`, index `images/index.json` (URL d'origine de chaque fichier, 404 notées, dernière présence de chaque jeu). Au scan, `ImageCache::apply` en dernier : une image distante déjà en cache (même URL d'origine) passe sur `local_art` + URL `ludex` ; les images locales du launcher restent prioritaires et ne sont jamais copiées. Fil `resolve_images` après chaque scan et après `resolve_art` (`images_busy`) : 4 téléchargements à la fois, jaquettes d'abord, arrêt après 3 erreurs réseau de suite, puis `game-art` par image. Règles : téléchargement seulement depuis les URL de l'état, hôtes en liste blanche stricte (`cdn.cloudflare.steamstatic.com`, `shared.akamai.steamstatic.com`, sans requête ni `..`), redirections jamais suivies, 8 Mo au plus, JPEG/PNG/WebP vérifiés par signature, écriture tmp + renommage, id nettoyé (`clean_id` : ASCII minuscule, empreinte FNV si modifié, noms réservés Windows évités). 404 (ou 403, 410, redirection, image invalide) notée et redemandée après 7 jours. Purge : dossier d'un jeu absent de la bibliothèque depuis 60 jours supprimé (jamais `images/custom/`), pas de plafond global (la taille suit la bibliothèque). Écriture commune `images::store(dir, kind, octets, ext)`. Les origines CDN restent dans `img-src` pour le premier affichage. Événement `game-details` : `{ id, details }`, envoyé quand une fiche arrive ou change.
- **Jaquettes hors Steam** (`src-tauri/src/art.rs`) : pour chaque jeu sans jaquette (hors Steam), titre cherché dans la recherche publique de la boutique Steam (`storesearch`, aucun compte, crate `ureq`), correspondance stricte (`same_game` : égalité, nom Steam qui finit par le titre, faute de frappe sans changer les nombres), table `DELISTED` pour les jeux retirés de la vente (FC, FIFA, Football Manager…). Chemins exacts des images lus dans `IStoreBrowseService/GetItems` (jeux récents : chemins hachés sur `shared.akamai.steamstatic.com`), sinon adresse classique du CDN. Cache `art-cache.json` (dossier de données) : trouvé = gardé, introuvable = recherché après 30 jours, `MATCHING_VERSION` à augmenter pour tout relancer. Recherche dans un fil après chaque scan, 350 ms entre deux titres. Sans jaquette : l'icône de l'exe sur la jaquette générée (`iconUrl`). L'appid retenu est gardé dans `Game.steam_appid`.
- **Jaquettes perso** (`src-tauri/src/covers.rs`) : jaquette et image de fond choisies pour n'importe quel jeu (jeux Riot sans visuel compris). `choose_cover(id, kind)` (`kind` = `cover` | `hero`, enum serde fermée `covers::Kind`) ouvre le sélecteur natif côté Rust (filtre PNG, JPEG, WebP ; aucun chemin ne passe par le front), vérifie le fichier (`check_image` : chemin absolu, extension d'image, 16 Mo au plus, signature, dimensions lues dans l'en-tête PNG/JPEG/WebP entre 16 et 16 384 px ; extension de la copie tirée de la signature), le COPIE dans `<données>/images/custom/<clean_id(id du jeu)>/<cover|hero>.<jpg|png|webp>` (tmp + renommage, `images::store`) : le fichier d'origine n'est jamais relu. Choix gardé dans `user-data.json` (`covers` : `{ <id>: { cover?: { ext, at }, hero?: … } }`, `at` = millisecondes du choix), qui versionne l'URL (`http://ludex.localhost/<plateforme>/<id>/<cover|hero>?v=<at>`, la requête est ignorée par le protocole) pour que la WebView n'affiche pas l'ancienne image. Priorité : image perso > images locales du launcher > cache disque > CDN > jaquette générée ; posée en dernier dans `rescan` (`covers::apply` après `images.apply`) sur `local_art` et l'URL, servie par le protocole `ludex` existant. `Game.custom_art` (`customArt` : types remplacés). L'image remplacée est gardée en mémoire (`AppState.originals`, refait à chaque scan, verrouillé après `games`) : `reset_cover(id, kind)` la rend sans rescan, réapplique `art.rs` et le cache disque, puis relance la recherche de jaquettes et les téléchargements. Une jaquette perso coupe la recherche en ligne (`art::needs_art` faux) et le téléchargement de la jaquette distante. Fichier perso disparu = ignoré au scan. Les deux commandes attendent `scan_lock`, enregistrent puis envoient `game-art` (et renvoient le même contenu ; `choose_cover` : `null` si annulé). Purge (`covers::purge`, dans `tidy_images`) : seul un dossier `custom/` dont le jeu n'est ni dans `covers` ni dans la bibliothèque est supprimé (restes) ; un jeu manuel retiré ou désinstallé garde ses images perso. Front : boutons « Changer la jaquette » et « Changer l'image de fond » de `GameStrip` (après Renommer), « Jaquette d'origine » (ou « Image de fond d'origine », ou les deux) quand une image perso existe, toasts de confirmation.
- **Fiches** (`src-tauri/src/metadata.rs`, `Game.details` : genres, `tags`, `moods`, `controller`, développeurs, éditeurs, `releaseDate` en secondes Unix, description courte) pour tout jeu avec `Game.steam_appid` (Steam, table Rockstar, jeux retrouvés par `art.rs`, jamais sérialisé). API publique `IStoreBrowseService/GetItems` (`include_basic_info`, `include_release`, `include_tag_count` 20, `language` french ; `categories` arrive sans rien demander), 40 appids par requête, 1 s entre deux lots. Les tags n'y sont que des numéros : noms français lus par `IStoreService/GetTagList?language=french` (~450 tags, public, sans clé) avant les fiches, gardés dans le cache (`tagNames`) et relus après 30 jours (ancienne liste gardée si la relecture échoue ; aucune liste = lecture des fiches arrêtée). Le cache garde les données brutes (`Item` : ids des tags par votes décroissants, catégories « joueurs » et « manette », studio, éditeur, date, description) ; `Details` en est tiré à chaque `apply` : genres = étiquettes de genre de `GENRES` (Action, Aventure, Stratégie, RPG…, sans Free-to-play, Accès anticipé ni Indépendant), trois au plus ; tags = dix premiers noms connus (genres compris) ; manette = catégorie 28 `full`, sinon 18 `partial`, sinon `null` ; date = sortie d'origine sinon sortie Steam. Changer `GENRES`, `MAX_TAGS` ou les ambiances ne demande donc pas de relire. Cache `metadata-cache.json` : appid redemandé après 30 jours, une fiche connue n'est jamais effacée par une réponse vide, `CACHE_VERSION` (2 depuis les tags) pour tout relancer. Fil après chaque scan et après la recherche des jaquettes (nouveaux appids), `meta_busy` contre les doublons ; une erreur réseau arrête la lecture.
- **Sauvegardes** (`src-tauri/src/saves.rs`) : emplacements tirés du manifeste communautaire Ludusavi (`mtkennerly/ludusavi-manifest`, YAML d'environ 17 Mo). Revérifié au plus une fois par semaine (`If-None-Match` : un manifeste inchangé ne se retélécharge pas), lu entrée par entrée (`serde_yaml_ng`, visiteur) puis réduit à un index compact `saves/manifeste.json` du dossier de données (règles Windows seulement, jeux avec fichiers ou registre, alias ; ~6,5 Mo, `INDEX_VERSION`), le YAML n'est pas gardé ; hors ligne, l'index enregistré sert. En mémoire (`AppState.saves`, `saves::Known`), seulement les entrées des jeux de la bibliothèque : appid Steam (secondaires compris), id GOG, titre normalisé (alias compris), sinon nom du dossier d'installation ; fil `resolve_saves` après chaque scan (`saves_busy`). `Scope` : motifs développés (`<base>`, `<game>`, `<root>` = dossier de Steam, `<home>`, `<winAppData>`, `<winLocalAppData>`, `<winLocalAppDataLow>`, `<winDocuments>` = dossier connu, OneDrive compris, `<winPublic>`, `<winProgramData>`, `<winDir>`, `<osUserName>`, `<storeUserId>` = `*`, `<storeGameId>`), valeurs échappées pour `glob` (casse ignorée), règle d'une autre boutique écartée, réglage livré dans `<base>` (tag `config` seul) écarté, motif non absolu ou avec `..` refusé, chemin trouvé trop large refusé (lecteur, profil, AppData, Documents, dossier du jeu, `userdata` ou un de leurs parents), liens symboliques et jonctions jamais suivis, fichier déjà dans un dossier trouvé non repris. Registre ignoré (signalé `registry`). Copie : `<dossier>/<titre nettoyé>/<AAAA-MM-JJ_hh-mm-ss>[-n]/` en heure locale (crate `time`), `copie.json` (`{ gameId, title, created, reason: auto|manual|before_restore, size, files: [{ path, stored, size, modified }] }`) et fichiers sous `fichiers/<lecteur>/<chemin>`, écrite en `.tmp` puis renommée (restes `.tmp` effacés à la copie suivante), 1 Go ou 20 000 fichiers au plus, dossier des copies jamais copié dans lui-même. Copie identique à la précédente (chemins, tailles, dates) non refaite (`unchanged`). 5 copies par jeu (`rotate`, copies protégées jamais supprimées), copies d'un jeu gardées dans le même dossier même renommé, listées par `gameId` (`list_all` : un seul parcours). Copie automatique : `session::Update.finished` (session d'une minute au moins, close au relevé ou à la reprise) → fil `auto_backup` si `autoSaves` et jeu connu, événement `saves-backup` `{ id, title, copy, unchanged, error }` ; rien si aucune sauvegarde trouvée. Restauration (`restore_saves(id, backupId)`) : id de copie validé (`valid_copy_id`), refusée si le jeu tourne (`Tracker::active`, puis relevé ponctuel des processus `session::game_running`), tout vérifié avant d'écrire : chemin d'origine absolu sur un lecteur local, sans `..`, reconnu par une règle du manifeste de ce jeu (le chemin ou un parent), aucun lien symbolique ni jonction sur tout le chemin, fichier source ordinaire sous `fichiers/` ; puis copie de sécurité de l'état actuel (`before_restore`, sauf si rien à copier ou identique), écriture tmp + renommage, rotation qui protège la copie restaurée et la copie de sécurité. Les fichiers présents mais absents de la copie restent. Dossier par défaut `Documents\Ludex\Sauvegardes` (`default_dir`), changé par `choose_saves_dir` (sélecteur de dossier natif côté Rust, `check_dir` : absolu, dossier réel, écriture testée ; partage réseau accepté), le front ne reçoit que le texte. `saves_lock` : jamais deux copies ou restaurations à la fois.
- **Ambiances** (`src-tauri/src/moods.rs`, `Details.moods` : `chill`, `intense`, `story`, `friends`, libellés Chill, Intense, Histoire, Entre amis dans `MOOD_LABEL` de `api.ts`). En Rust plutôt qu'en TS : tables testées par `cargo test` (le front n'a pas d'outil de test), ids de tags indépendants de la langue, résultat prêt comme les genres. Tables `CHILL`, `INTENSE`, `STORY`, `FRIENDS` d'ids de tags commentés ; seuls les 12 tags les plus votés comptent (`MOOD_RANK`) ; plusieurs ambiances possibles ; Chill écarté par Intense et par la survie (`NOT_CHILL` : Frostpunk, Terraria) ; Entre amis aussi par les catégories « joueurs » coop ou écran partagé (9, 38, 39, 48, 24, 37), pas par le multijoueur compétitif seul ni par les tags « Multijoueur » et « Jeu d'équipe » (portés par la moitié de la bibliothèque).
- **Rescan automatique** (`src-tauri/src/watch.rs`, crate `notify`, lancé après le premier `scan_library`) : surveille sans récursion les `steamapps` de chaque bibliothèque Steam (`appmanifest_*.acf`), les manifestes Epic (`*.item`), `ProgramData\Riot Games` (`RiotClientInstalls.json`) et, avec récursion, son `Metadata` (`*.product_settings.yaml`), et les dossiers dont les sous-dossiers sont des jeux (`local::library_dirs` : « Jeux », « Games », « Jeux Epic » ; sous-dossier créé, supprimé ou renommé). Un manifeste touché est relu après 5 s de calme : rescan seulement si son état installé change (Steam `StateFlags` bit 4, Epic `bIsIncompleteInstall`), donc ni pendant un téléchargement ni pour une mise à jour. Anti-rebond : chaque changement repousse l'échéance de 5 s ; un scan déjà en cours (verrou `scan_lock`) = retenté au calme suivant. Fil endormi sur le canal de `notify` quand rien ne bouge ; dossier absent ou erreur = message console. Liste des dossiers relue après chaque scan. Retour sur la fenêtre (`Focused`) plus de 5 min après le dernier scan = rescan (GOG, Ubisoft, Rockstar, Xbox, lus dans le registre). Même chemin que `scan_library` (`rescan` dans `lib.rs`), puis événement `library-changed` : `{ added, removed, scan }` (titres hors jeux masqués, `ScanResult` complet) ; le front remplace la bibliothèque sans spinner et affiche « Nouveau jeu : Hades », « 3 nouveaux jeux » ou « Jeu retiré : Portal ». `library::scan` vide le cache de 10 s de `local::candidates`.
- **Stockage** (`src-tauri/src/storage.rs`, section « Stockage ») : commande `storage` (sans argument) = `{ disks, candidates, measuring }`. `disks` : disques (crate `sysinfo`, fonction `disk`) qui portent au moins un jeu, disque d'un jeu = point de montage le plus long qui contient son dossier ; lettre, nom, total, libre, place des jeux de taille connue (masqués compris) par launcher, jeux sans taille, `low` = moins de 10 % libres. `candidates` : jeux non masqués ni outils, de taille connue, pas lancés depuis 182 jours ou jamais, le plus gros d'abord, avec lecteur, `launcherDates` (Steam, GOG Galaxy notent les lancements ; sinon « Jamais depuis Ludex ») et `uninstall`. Tailles : Steam `SizeOnDisk`, Epic `InstallSize` ; pour les autres (`size_on_disk` vide ou `Game.size_measured`), somme des fichiers du dossier d'installation (liens et jonctions non suivis) dans le fil `resolve_sizes` après chaque scan (`sizes_busy`, un dossier à la fois), puis événement `game-size` `{ id, sizeOnDisk }` (le front met à jour le jeu : tri « Taille » compris). Dossier refusé s'il est trop large (`session::root_key`) ou contient le dossier d'un autre jeu. ## Design system

- Tokens dans `src/styles/tokens.css` (préfixe `--lx-*`), styles dans `src/styles/app.css`.
- Logo : une touche de clavier turquoise avec le triangle « Jouer » (`assets/logo/ludex-mark.svg`, version avec le nom `ludex-lockup.svg`, composant `LudexMark`). Icônes de l'app régénérées par `npx tauri icon assets/logo/ludex-mark.svg` (supprimer ensuite `icons/android` et `icons/ios`).
- Palette validée : base monochrome (#0B0B0B, #1A1A1A, #242424, #333333, blanc) + accent turquoise #14B8A6. Thème clair via `[data-theme="light"]`. D'autres thèmes viendront plus tard : toujours passer par les tokens, jamais de couleur en dur.
- `--lx-ambient` : couleur dérivée du jeu sélectionné, réservée au contour de sélection. Bouton Jouer en blanc cassé (`--lx-text` sur `--lx-bg`).
- Passe unslop appliquée : grille de 4px, icônes 18px trait 1.5, graisses 400 à 600, pas de majuscules espacées, chiffres tabulaires, rayons s/m/l = 8/10/12, une seule courbe `--lx-ease`, survol sans déplacement (contour ou voile qui s'éclaircit), léger `scale` au clic.

Relevé réel (`journal_this_pc`) : 571 jours actifs en 20 pages, du 31 août 2013 à aujourd'hui, presque tous grâce aux dates des succès Steam (aucune session dans `sessions.json` sur ce PC) et aux 128 captures ; première page en ~20 ms (debug) une fois la bibliothèque et les captures relevées (~3 s avec le scan), détail des succès lu 148 fois pour tout le journal. Front vérifié par `tsc` et le build seulement : rien vu à l'écran (section, frise, icônes des succès, vignettes et visionneuse, chargement au défilement, navigation clavier et manette, bouton « Voir son journal » de la fiche). Limites : jours sans session ni succès ni capture absents ; une partie en cours n'apparaît qu'à sa fin ; seulement les parties lancées depuis Ludex ; succès des jeux Steam installés seulement ; date d'une capture = date du fichier (une copie la change) ; relecture (fin de partie, nouveaux succès) = retour à la première page ; avec 10 sections, « Sauvegardes » n'a plus de raccourci Ctrl+chiffre.
- Problèmes connus : jeux Riot sans images (jaquette générée avec icône, sauf jaquette perso). Titre tiré d'un dossier mal nommé (« Crusader King ») non reconnu sur Steam : le renommer dans sa fiche. Amis pas commencés ; succès hors Steam pas commencés (la vitrine ne compte que Steam).
